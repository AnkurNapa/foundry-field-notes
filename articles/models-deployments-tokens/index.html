Models, deployments and tokens: why the bill follows the tokens

A model sits in the catalogue. A deployment is your named, rate-limited way to call it. Tokens are what you send and receive. On pay-per-token deployments, they are what you pay for.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 0 Ankur Napa ModelsCost

Short answer

A model is an entry in the Foundry catalogue, such as gpt-5.4-mini. A deployment is your named copy of that model on your Foundry resource. It has a deployment type, a version and a rate limit. Your code calls the deployment name, not the model.

A token is a chunk of text. For typical English text, a token is roughly four characters. Every request has input tokens (what you send) and output tokens (what comes back). On pay-per-token deployments, input and output tokens are billed at separate rates per million tokens. So the bill follows the tokens. More words in, more words out, more cost.

This step maps to the AI-103 skill area Plan and manage an Azure AI solution, in particular choosing deployment options and managing quotas, rate limits and cost footprints.

Output tokensThe answer, plus any reasoning tokens a reasoning model spendsThe reply to the customer.

Three things decide the price of a token: the model, the deployment type and the token kind. The Azure OpenAI pricing page lists input, cached input and output rates per million tokens for each model and deployment type. Prices vary by region and change over time, so read the page on the day you estimate. Global Batch is the one fixed ratio worth remembering: it costs 50 percent less than Global Standard in exchange for a 24-hour target turnaround.

Two details catch people:

  • Reasoning tokens count as output. A reasoning model can think for hundreds or thousands of tokens you never see. They take room in the context window and are billed as output tokens.
  • Managed compute is different. Models deployed to managed compute (dedicated virtual machines) bill by VM core hours, not by tokens. Most Foundry work uses serverless deployments, which bill by tokens.

A worked example

The sample file models-deployments-tokens.csv holds 30 synthetic Harbour Goods support requests from one day, with the token counts each request used.

MeasureValue
Requests30
Input tokens14,030
Output tokens4,380
Total tokens18,410
Average input per request467.7
Average output per request146.0
Share of tokens that are output23.8 percent.

By intent, a warranty question averages 805.7 tokens and an order status question 461.4. Warranty answers are longer and the questions carry more detail. Same model, same deployment, almost twice the tokens.

The bill for that day is the input tokens times the input rate, plus the output tokens times the output rate, each per million. No other number matters on a pay-per-token deployment. Change the prompt, the history you resend or the length of the answer. The bill moves with it.

A ten-minute tour

  1. Sign in to Microsoft Foundry with the New Foundry toggle on. Open your project.
  2. Select Discover to open the model catalogue. Search for gpt-5.4-mini and open its model card.
  3. Read the Quick facts and the Details tab. Note the context window and the versions.
  4. Open the Deployments tab on the card. It lists the deployments of this model you already have.
  5. Select Build, then Models. Open one deployment and note three things: its name, its deployment type and its version.
  6. Select Manage, then Quota. On the Token per minute tab, select the deployment to see its allocation and usage.
  7. Open the model retirement schedule. Find your model and version. In October 2026, gpt-5.4-mini version 2026-03-17 is GA with a retirement date of 21 September 2027.

That last step matters. A deployment is pinned to a version. Every version has an end date.

What people get wrong

"The deployment name is the model name." It often is, because the quickstarts name the deployment after the model. It doesn't have to be. Your code sends the deployment name in the model field.

"TPM is my bill." TPM is a rate limit, not a spend. A deployment with 100,000 TPM that sits idle costs nothing on Global Standard. The rate limit also uses an estimate that includes the max_tokens you ask for, so you can hit it before your billed tokens would suggest.

"A short question is a cheap request." Not if you resend a long system prompt and the whole conversation history every turn. In the sample above, input tokens outnumber output tokens by more than three to one.

"Provisioned is just a bigger Standard." Provisioned deployments reserve capacity in provisioned throughput units (PTUs) and bill by the hour whether you use them or not. The trade is predictable latency for a fixed cost.

On the brewhouse floor

A winery's tasting-notes assistant answers the same twenty questions about each vintage, all day, at the cellar door. Every answer resends the full technical sheet for the wine, so input tokens dwarf the short replies. Winery A cut the sheet to the facts staff actually quote. The token count per answer fell with it. The model didn't change. The bill followed the tokens.
