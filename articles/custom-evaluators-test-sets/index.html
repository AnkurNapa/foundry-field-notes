Custom evaluators and test sets for your own definition of good

Write a 30-row test set that says what a correct Harbour Goods answer must and must not contain, turn it into a code-based grader you can unit test on your laptop, add a prompt-based judge for tone and run both against the support agent.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa EvaluationAgentsSDK

Short answer

Built-in evaluators know what fluent, grounded and safe look like. They do not know that a Harbour Goods answer about a late order must quote the order ID back, or that "same-day delivery" is a promise the company never makes. That knowledge lives in two places you write yourself: the test set and a custom evaluator.

Foundry supports three kinds of custom evaluator, all in preview. A code-based evaluator is a Python grade() function that returns a float from 0.0 to 1.0. A prompt-based evaluator is a judge prompt that returns a JSON result and reason. An endpoint-based evaluator calls your own HTTP service. Start with code for anything you can check with a string, because code is cheap, deterministic and testable on your laptop. Use a prompt only for judgements code cannot make, such as tone.

What you will build

  • The test set custom-evaluators-test-sets.jsonl: 30 rows, each with must_include and must_not_include phrase lists and a known-good reference_response.
  • A code-based evaluator, hg_policy_phrases, that scores each reply against those lists. You test it locally before Foundry ever sees it.
  • A prompt-based evaluator, hg_support_tone, that scores tone and hand-over behaviour on a 1 to 5 scale.
  • One evaluation run against the harbour-goods-support agent using both.

Before you start

  • The harbour-goods-support agent and a judge deployment such as gpt-5.4-mini, both from Run your first evaluation.
  • The Foundry User role on the project.
  • pip install "azure-ai-projects>=2.0.0" azure-identity

Step 1: write the test set

A test set is a statement of what good means, written before you see the agent's answers. Each row of the sample looks like this:

{"query": "I bought a shirt 31 days ago. Can I return it?", "category": "returns", "kind": "edge", "must_include": ["30 days"], "must_not_include": ["yes, you can return"], "reference_response": "Sorry, returns are accepted within 30 days with a receipt, so 31 days is outside the window."}

The 30 rows break down like this:

kindRowsPurpose
normal18Everyday questions the agent must get right every time.
edge9Boundaries: day 30 and day 31 of the returns window, month 13 of the warranty, a late Chennai order, the bad store code ST-099.
adversarial3Prompt injection, a request for a refund code, a request for another customer's phone number.

By category there are 6 returns, 6 delivery, 5 orders, 3 warranty, 3 safety, 2 hours, 2 out of scope, 2 tone and 1 price row. 24 rows have at least one must_include phrase and 17 have at least one must_not_include phrase.

Rules that kept this set useful:

  • Write the phrase lists from policy, not from the agent's output. If you copy what the agent said, you are testing that it agrees with itself.
  • Put boundaries on both sides. Day 30 is in, day 31 is out. A test set with only day 12 never notices an off-by-one.
  • Keep a known-good answer per row. reference_response is how you prove the grader works before you point it at the agent.
  • Version the file. Upload it as a versioned dataset and bump the version when you change a row, so old and new scores never get compared by accident.

Step 2: write the grader and test it locally

The grader lives in a string, so the same code runs on your laptop and in Foundry.

GRADE_CODE = '''
def grade(sample: dict, item: dict) -> float:
    """Phrase rules: any banned phrase scores 0.0, else the share of required phrases found."""
    try:
        response = item.get("sample", {}).get("output_text") or item.get("reference_response") or ""
        text = response.lower()
        for banned in item.get("must_not_include", []):
            if banned.lower() in text:
                return 0.0
        required = item.get("must_include", [])
        if not required:
            return 1.0
        hits = sum(1 for phrase in required if phrase.lower() in text)
        return hits / len(required)
    except Exception:
        return 0.0
'''

namespace = {}
exec(GRADE_CODE, namespace)
grade = namespace["grade"]

Learn says that for an agent target the generated reply is read through item.get("sample", {}).get("output_text") and that this access pattern may change. The fallback to reference_response is what lets you test locally. The try block matters too: if grade() raises, Foundry records 0.0 and marks the row as an error.

Now test it on the 30 known-good answers and on three deliberately bad ones:

import json

rows = [json.loads(line) for line in open("custom-evaluators-test-sets.jsonl")]
scores = [grade({}, row) for row in rows]
assert all(score == 1.0 for score in scores), scores

bad = [
    ("Yes, returns are accepted for 45 days.", ["30 days", "receipt"], ["45 days"]),
    ("Delivery takes 3 working days.", ["5 working days"], ["3 working days"]),
    ("Support opens at 9 AM.", ["9 AM", "9 PM"], []),
]
for reply, must, must_not in bad:
    item = {"sample": {"output_text": reply}, "must_include": must, "must_not_include": must_not}
    print(grade({}, item))

Expected output: the assert passes on all 30 rows, then 0.0, 0.0 and 0.5. The first bad reply uses a banned phrase. The second says 3 working days for Mysuru, which is the banned answer for a non-metro city. The third gets the opening time right and leaves out the closing time.

Step 3: register the code-based evaluator

This follows Learn's create_version shape. Code-based evaluators use a continuous metric from 0.0 to 1.0.

import os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import EvaluatorCategory, EvaluatorDefinitionType

project_client = AIProjectClient(
    endpoint=os.environ["AZURE_AI_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)

code_evaluator = project_client.beta.evaluators.create_version(
    name="hg_policy_phrases",
    evaluator_version={
        "name": "hg_policy_phrases",
        "categories": [EvaluatorCategory.QUALITY],
        "display_name": "Harbour Goods policy phrases",
        "description": "Scores replies against must-include and must-not-include phrase lists",
        "definition": {
            "type": EvaluatorDefinitionType.CODE,
            "code_text": GRADE_CODE,
            "init_parameters": {
                "type": "object",
                "properties": {
                    "deployment_name": {"type": "string"},
                    "pass_threshold": {"type": "number"},
                },
                "required": ["deployment_name", "pass_threshold"],
            },
            "metrics": {
                "result": {
                    "type": "continuous",
                    "desirable_direction": "increase",
                    "min_value": 0.0,
                    "max_value": 1.0,
                }
            },
            "data_schema": {
                "type": "object",
                "required": ["item"],
                "properties": {
                    "item": {
                        "type": "object",
                        "properties": {
                            "must_include": {"type": "array", "items": {"type": "string"}},
                            "must_not_include": {"type": "array", "items": {"type": "string"}},
                            "reference_response": {"type": "string"},
                        },
                    },
                },
            },
        },
    },
)

deployment_name is required even though the code never calls a model. Learn says the run orchestration needs it, so pass any deployment in the project.

In the portal, the same thing lives under Evaluation > Evaluator catalog > Custom evaluator > Create. Choose Code-based and paste the function into the editor.

Step 4: register a prompt-based judge for tone

Phrase rules cannot tell a curt refusal from a helpful one. A judge prompt can.

tone_prompt = (
    "You are grading a Harbour Goods customer support reply.\n"
    "Score 1 to 5:\n"
    "5 - Polite, direct, apologises when something went wrong, offers a clear next step\n"
    "4 - Polite and clear, next step implied\n"
    "3 - Correct but curt\n"
    "2 - Unhelpful or dismissive\n"
    "1 - Rude, or promises something it cannot do\n\n"
    "Customer: {{query}}\n"
    "Reply: {{response}}\n\n"
    "Output Format (JSON):\n"
    '{"result": <integer from 1 to 5>, "reason": "<one sentence>"}\n'
)

tone_evaluator = project_client.beta.evaluators.create_version(
    name="hg_support_tone",
    evaluator_version={
        "name": "hg_support_tone",
        "categories": [EvaluatorCategory.QUALITY],
        "display_name": "Harbour Goods support tone",
        "description": "Tone and next-step behaviour of a support reply",
        "definition": {
            "type": EvaluatorDefinitionType.PROMPT,
            "prompt_text": tone_prompt,
            "init_parameters": {
                "type": "object",
                "properties": {
                    "deployment_name": {"type": "string"},
                    "threshold": {"type": "number"},
                },
                "required": ["deployment_name", "threshold"],
            },
            "data_schema": {
                "type": "object",
                "properties": {"query": {"type": "string"}, "response": {"type": "string"}},
                "required": ["query", "response"],
            },
            "metrics": {
                "custom_prompt": {
                    "type": "ordinal",
                    "desirable_direction": "increase",
                    "min_value": 1,
                    "max_value": 5,
                }
            },
        },
    },
)

Step 5: run both against the agent

Upload the test set, then run it against the agent with both custom evaluators. The run call is the same as in Run your first evaluation.

import time
from openai.types.eval_create_params import DataSourceConfigCustom

client = project_client.get_openai_client()
judge = os.environ["AZURE_AI_MODEL_DEPLOYMENT_NAME"]

dataset = project_client.datasets.upload_file(
    name="hg-custom-test-set", version="1", file_path="./custom-evaluators-test-sets.jsonl"
)

evaluation = client.evals.create(
    name="hg-custom-evaluators",
    data_source_config=DataSourceConfigCustom(
        type="custom",
        item_schema={
            "type": "object",
            "properties": {
                "query": {"type": "string"},
                "category": {"type": "string"},
                "kind": {"type": "string"},
                "must_include": {"type": "array", "items": {"type": "string"}},
                "must_not_include": {"type": "array", "items": {"type": "string"}},
                "reference_response": {"type": "string"},
            },
            "required": ["query"],
        },
        include_sample_schema=True,
    ),
    testing_criteria=[
        {
            "type": "azure_ai_evaluator",
            "name": "hg_policy_phrases",
            "evaluator_name": "hg_policy_phrases",
            "initialization_parameters": {"deployment_name": judge, "pass_threshold": 1.0},
        },
        {
            "type": "azure_ai_evaluator",
            "name": "hg_support_tone",
            "evaluator_name": "hg_support_tone",
            "data_mapping": {"query": "{{item.query}}", "response": "{{sample.output_text}}"},
            "initialization_parameters": {"deployment_name": judge, "threshold": 4},
        },
    ],
)

run = client.evals.runs.create(
    eval_id=evaluation.id,
    name="hg-custom-run-1",
    data_source={
        "type": "azure_ai_target_completions",
        "source": {"type": "file_id", "id": dataset.id},
        "input_messages": {
            "type": "template",
            "template": [{"type": "message", "role": "user",
                          "content": {"type": "input_text", "text": "{{item.query}}"}}],
        },
        "target": {"type": "azure_ai_agent", "name": "harbour-goods-support"},
    },
)

while run.status not in ("completed", "failed"):
    time.sleep(5)
    run = client.evals.runs.retrieve(run_id=run.id, eval_id=evaluation.id)

items = list(client.evals.runs.output_items.list(run_id=run.id, eval_id=evaluation.id))
print(run.status, run.report_url, len(items))

A pass_threshold of 1.0 means a reply passes the phrase check only if it hits every required phrase and no banned one. That is strict on purpose. Loosen it only after you have read the failures.

Check it worked

CheckExpected
Local assert on reference_responsePasses on all 30 rows.
Local bad replies0.0, 0.0 and 0.5.
Evaluator cataloghg_policy_phrases and hg_support_tone listed as custom evaluators.
Run output items30
Rows to read firstThe 9 edge and 3 adversarial rows. That is where policy agents fail.

The phrase scores are deterministic for a given reply. The agent's replies are not, so expect the pass rate to move a few rows between runs. The tone scores move a little more, because a model is grading.

Where this breaks

  • Preview. All three custom evaluator types are preview. The item["sample"] access pattern is flagged by Learn as subject to change.
  • Sandbox limits. Code-based evaluators get no network, 2 minutes per call, 2 GB of memory, 1 GB of disk, 2 CPU cores and under 256 KB of code. Only listed packages are available, among them numpy, pandas, rapidfuzz, jsonschema, pydantic and nltk.
  • Phrase rules are brittle. "thirty days" fails a rule written as "30 days". Use rapidfuzz from the allowed package list, or a prompt-based judge, when wording varies.
  • Endpoint evaluators must answer in 30 seconds. Use them when you need network access or your own model. Authenticate with Microsoft Entra ID through a project connection rather than a key where you can.
  • Rubric evaluators are another option. Learn's agent evaluation guide recommends a rubric evaluator (preview), weighted dimensions an LLM judge scores from 1 to 5, as the primary agent measure. A rubric can sit next to the code grader.

On the brewhouse floor

Brewery A's packaging line assistant answers shift questions from the QA manual. Some answers have hard rules a code grader can check: a dissolved oxygen limit must be quoted with its unit. The words "release the batch" must never appear when a reading is out of spec. A prompt judge cannot be trusted with a number like that, but ten lines of Python can. Keep the judge for whether the reply tells the operator who to call.
