Content filters and blocklists: set them, then prove they fire

Build a custom guardrail with tighter severity thresholds and a blocklist of internal terms, assign it to a test deployment, then run 24 test prompts from Python to prove which ones are blocked.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 1 Ankur Napa SafetyModelsSDK

Short answer

In the new Foundry portal, content filters live inside a guardrail. A guardrail is a named set of controls. Each control names a risk, the intervention points to scan and an action. Every model starts on the Microsoft default, which filters hate, sexual, violence and self-harm at Medium on prompts and completions. You can't edit the default. You create your own guardrail and assign it.

Severity thresholds are Low, Medium and High. A threshold flags content at that severity and above, so Low catches the most and High catches only the most severe. Off is available only to customers approved for modified guardrails.

A blocklist adds your own terms on top. It catches things no harm classifier knows about: internal project names, cost data, anything you never want in or out of the model. Blocklists work with Azure OpenAI models only.

For AI-103, this covers "Configure safety filters, guardrails, risk detection and content moderation".

What you will build

Harbour Goods wants its support model to be stricter than the default on violence and hate, because angry delivery complaints are common. It also never wants four internal phrases to reach the model: Project Kestrel (an unannounced loyalty scheme), supplier margin, cost price list and escalation matrix.

PieceSetting
Blocklist hg-internal-termsFour exact-match terms, applied to prompts
Guardrail hg-support-strictViolence and Hate at Low on user input and output. Sexual and Self-harm stay at Medium

Before you start

  • A Foundry project with a deployment of a current chat model such as gpt-5.4-mini. Use a test deployment. Assigning a guardrail changes behaviour immediately.
  • Foundry Account Owner or higher on the Foundry resource to create guardrails. Foundry User on the project to run the test script.
  • Python 3.10 or later, the Azure CLI and az login done.
  • Your project endpoint, in the form https://<resource>.services.ai.azure.com/api/projects/<project>.

Step 1: create the blocklist

  1. Sign in to Microsoft Foundry and open your project.
  2. Select Build in the upper-right menu, then Guardrails in the left pane.
  3. Open the Blocklists tab and select Create blocklist.
  4. Name it hg-internal-terms. Names allow letters, digits and - . _ ~.
  5. Add the four terms manually, or upload a .csv file with one term per row. Leave them as exact match, not regex.
  6. Save. New terms can take around five minutes to take effect.

Step 2: create the guardrail

  1. On the Guardrails page, select Create Guardrail. The wizard opens at Step 1, Add Controls. Default controls are already in the table on the right.
  2. In the risk dropdown, select Violence. Select the User input and Output intervention points, set the threshold to Low and keep the action Annotate and block.
  3. Select Add control. Because Violence on input and output can't be deleted, the portal asks to override the existing control. Select Confirm.
  4. Repeat for Hate at Low.
  5. Add a blocklist control that uses hg-internal-terms on user input. The portal label for this control may read Blocklist or Custom blocklist. If you can't find it, attach the list with the REST call in the next block.
  6. Select Next. On Step 2, select Add models and pick your test deployment. Select Save.
  7. Select Next, name the guardrail hg-support-strict and select Create.

If the portal won't attach the blocklist, attach it through the RAI policy API, which is how the REST API represents a guardrail. Use promptBlocklists so it applies to user prompts. This call replaces the policy's settings, so read the current policy first and keep its existing contentFilters entries in the body.

TOKEN=$(az account get-access-token --query accessToken -o tsv)

curl --request PUT "https://management.azure.com/subscriptions/<subscriptionId>/resourceGroups/<resourceGroup>/providers/Microsoft.CognitiveServices/accounts/<foundryResource>/raiPolicies/hg-support-strict?api-version=2024-10-01" \
  --header "Authorization: Bearer $TOKEN" \
  --header "Content-Type: application/json" \
  --data-raw '{
    "properties": {
      "basePolicyName": "Microsoft.Default",
      "promptBlocklists": [{ "blocklistName": "hg-internal-terms", "blocking": true }],
      "contentFilters": [ ]
    }
  }'

The blocklist API calls need Cognitive Services Contributor or Owner on the resource.

Step 3: try it in the playground

  1. On the Guardrails page, select the hg-support-strict row.
  2. In the panel on the right, select Try in Playground.
  3. Send Tell me about Project Kestrel launch dates. A message appears in the chat naming the risk and the intervention point.
  4. Send Where is my order HG-240318-0042?. The model answers normally.

Step 4: run the full test set from Python

Install the packages:

pip install azure-ai-projects azure-identity openai

Save this as test_guardrail.py next to the CSV. It uses keyless auth through DefaultAzureCredential. A blocked prompt raises BadRequestError with the code content_filter. For prompts that pass, the guardrail results arrive in a content_filters array, which is a Foundry extension the SDK doesn't type, so the script reads it from model_extra.

import csv
from openai import BadRequestError
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

PROJECT_ENDPOINT = "https://<resource>.services.ai.azure.com/api/projects/<project>"
DEPLOYMENT = "gpt-5.4-mini"

project = AIProjectClient(endpoint=PROJECT_ENDPOINT, credential=DefaultAzureCredential())
openai = project.get_openai_client()

results = {}
with open("content-filters-blocklists.csv", newline="") as f:
    for row in csv.DictReader(f):
        try:
            response = openai.responses.create(model=DEPLOYMENT, input=row["prompt"])
            filters = (response.model_extra or {}).get("content_filters", [])
            blocked = any(item.get("blocked") for item in filters)
            outcome = "blocked" if blocked else "answered"
        except BadRequestError as error:
            if error.code != "content_filter":
                raise
            outcome = "blocked"
        results[outcome] = results.get(outcome, 0) + 1
        print(f"{row['test_id']} expected={row['expected_result']:<18} got={outcome}")

print(results)

Check it worked

The CSV has 24 prompts. Run the script five minutes or more after you saved the blocklist.

GroupRowsExpected
Normal support questions14All answered, including Which store is ST-099?
Exact blocklist hits (T03, T04, T05, T08, T20)5All blocked with content_filter
Violent or hateful requests (T13 to T15)3Blocked by the filter, or answered with a refusal. Record which
Blocklist edge cases (T11, T22)2Upper case and a hyphenated variant. Record what happens

T11 and T22 are there to teach you something. Exact match doesn't promise to catch Project-Kestrel with a hyphen. If you need variants, add them as terms or write a regex. Learn notes regex patterns are case-sensitive by default, so test both cases.

Where this breaks

  • Blocklists are Azure OpenAI only. A partner model behind the same guardrail won't use the list.
  • Limits. One blocklist holds up to 10,000 terms. Each term is up to 1,000 characters. Need more terms? Create another list and add it to the same guardrail.
  • Agents override models. An agent uses its own guardrail, not its model's. If you test through an agent, assign hg-support-strict to the agent too.
  • The default can't be edited. Default.V2 is read only. If changes don't apply, check which guardrail is assigned.
  • Latency. Each intervention point adds roughly 50 to 100 ms. Don't switch on every control out of habit.
  • Languages. The harm classifiers are trained on English, German, Japanese, Spanish, French, Italian, Portuguese and Chinese. Test Hindi and other languages your customers use.
  • Filters that didn't run. If the filtering system can't finish in time, the request can complete unfiltered. Learn advises checking the results for an error object.

On the brewhouse floor

Brewery A's taproom assistant should never mention the contract recipe it brews for another label. It should never quote the cost per barrel on any beer either. Both go in a blocklist. The violence filter at Low catches the occasional furious message about a flat pint before it reaches the model. The test file holds 20 real taproom questions plus the forbidden phrases. It runs every time someone changes the guardrail.
