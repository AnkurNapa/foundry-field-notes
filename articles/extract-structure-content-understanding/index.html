Extract invoice fields with Content Understanding and confidence

Run three Harbour Goods supplier invoices through the prebuilt-invoice analyzer in Content Understanding, read each field with its confidence score and route anything doubtful to a person. One invoice ships to store ST-099, which does not exist. The pipeline has to catch it.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa KnowledgeSDKEvaluation

Short answer

Azure Content Understanding in Foundry Tools turns documents into structured fields. You send a file to an analyzer and get back Markdown of the whole document plus typed fields, each with a value, a confidence score from 0 to 1 and a source location on the page. For invoices you do not design a schema. The prebuilt prebuilt-invoice analyzer already knows invoice IDs, dates, totals and line items.

The confidence score is the point. Learn says to use confidence and source grounding to send low-confidence or poorly grounded fields to human review and let high-confidence results flow straight through. Content Understanding normalises dates and numbers to a canonical format for you. You cannot switch that off.

The service needs default model deployments on your Foundry resource, because analyzers use generative models underneath. Use the generally available API version 2025-11-01 unless you need a preview feature. For AI-103, this is Implement information extraction solutions: extract information with pipelines that combine OCR, layout analysis and field extraction, then produce clean, grounded representations for agents and RAG with Content Understanding.

What you will build

A Python script that analyses three supplier invoices, prints the fields that matter to accounts payable and decides for each invoice: post it, or send it to a person.

The answer key, with subtotals, GST at 18 per cent and line counts, is in extract-structure-content-understanding.csv. The three totals add up to INR 287,052.70.

Invoice 3 is the trap. It is a perfectly readable invoice for a store that does not exist. Content Understanding will extract ST-099 with high confidence, because the text really says ST-099. Catching it is your business rule, not the model's job.

Before you start

  • A Microsoft Foundry resource in a region Content Understanding supports. Creating one needs Contributor or higher on the resource group.
  • Default model deployments for Content Understanding. The quickest route is the Content Understanding settings page: select + Add resource, pick your Foundry resource, keep Enable autodeployment for required models if no defaults are available ticked and save. That deploys a standard model, a mini model and an embeddings model.
  • The Cognitive Services User role on the Foundry resource for keyless calls. Learn's keyless guidance notes that Owner and Contributor do not grant inference access.
  • Python 3.9 or later with pip install --pre azure-ai-contentunderstanding azure-identity, signed in with az login.
  • The resource endpoint in an environment variable called CONTENTUNDERSTANDING_ENDPOINT. Leave CONTENTUNDERSTANDING_KEY unset so the code uses Microsoft Entra ID.

Step 1: look at one invoice in the playground

  1. Sign in to Microsoft Foundry and open your project.
  2. Select Build, then Models on the left.
  3. Select the AI Services tab, then Content Understanding Playground.
  4. Choose the invoice analyzer and upload invoice 2.
  5. Read the results as formatted fields, then switch to the raw JSON.

Find InvoiceId, InvoiceDate, DueDate and the LineItems array. Each field has a confidence and a source value. The source looks like D(1,7.36,8.04,...): page number and polygon coordinates. That is how a reviewer jumps to the exact spot on the page.

Step 2: analyse all three from Python

The samples are published on this site, so the analyzer can read them by URL. This follows the prebuilt-invoice sample in the Content Understanding quickstart, with DefaultAzureCredential in place of a key.

import os
import re

from azure.ai.contentunderstanding import ContentUnderstandingClient
from azure.ai.contentunderstanding.models import AnalysisInput, ArrayField, ObjectField
from azure.identity import DefaultAzureCredential

client = ContentUnderstandingClient(
    endpoint=os.environ["CONTENTUNDERSTANDING_ENDPOINT"],
    credential=DefaultAzureCredential(),
)

BASE = "https://ankurnapa.github.io/foundry-field-notes/samples/"
STORES = {"ST-003", "ST-007", "ST-011", "ST-014", "ST-019", "ST-022"}
REVIEW_BELOW = 0.80

def analyse(name):
    poller = client.begin_analyze(
        analyzer_id="prebuilt-invoice",
        inputs=[AnalysisInput(url=BASE + name)],
    )
    return poller.result().contents[0]

for n in (1, 2, 3):
    doc = analyse(f"extract-structure-content-understanding-invoice-{n}.pdf")
    fields = doc.fields or {}
    reasons = []

    for key in ("InvoiceId", "InvoiceDate", "DueDate"):
        f = fields.get(key)
        if f is None:
            reasons.append(f"{key} missing")
            continue
        print(f"invoice {n} {key}: {f.value} (confidence {f.confidence or 0:.2f})")
        if (f.confidence or 0) < REVIEW_BELOW:
            reasons.append(f"{key} below {REVIEW_BELOW}")

    total = fields.get("TotalAmount")
    if isinstance(total, ObjectField) and total.value:
        amount = total.value.get("Amount")
        print(f"invoice {n} TotalAmount: {amount.value if amount else None}")
    else:
        reasons.append("TotalAmount missing")

    items = fields.get("LineItems")
    count = len(items.value) if isinstance(items, ArrayField) and items.value else 0
    print(f"invoice {n} line items: {count}")

    store_codes = set(re.findall(r"ST-\d{3}", doc.markdown or ""))
    if not store_codes or not store_codes <= STORES:
        reasons.append(f"unknown store code {sorted(store_codes - STORES)}")

    print(f"invoice {n}: {'REVIEW ' + '; '.join(reasons) if reasons else 'POST'}\n")

Two checks run here. They are different kinds of check. The confidence check asks whether the analyzer is sure it read the field correctly. The store check asks whether what it read makes sense for Harbour Goods. Learn's guidance covers the first. Only you can write the second.

Check it worked

Compare the output with the answer key.

2BGE/26-27/04412026-09-22163070.14POST, unless a confidence falls below 0.80
3MPC-77812026-09-2537819.02REVIEW: unknown store code ST-099

Dates come back as ISO dates because Content Understanding normalises them. Your exact confidence numbers will differ from run to run and invoice to invoice. Do not hard-code them in tests. In Learn's own quickstart output, the customer name on the sample invoice came back at 0.39 confidence while the invoice date came back at 0.91. A threshold that never fires is not a threshold.

If invoice 3 posts, the store rule is broken. If all three go to review on confidence alone, lower the threshold carefully and look at which field keeps failing. That field is your next custom analyzer.

Where this breaks

  • Field names are the analyzer's, not yours. Learn links the full prebuilt-invoice schema from the prebuilt analyzers page. Read it before you map fields to your ERP. A field you expect may live under a different name or inside an object.
  • No defaults, no analysis. Without default model deployments on the resource, prebuilt analyzers cannot run. The autodeploy option in the settings page is the fastest fix.
  • Size and page limits. Asynchronous analysis takes PDFs up to 200 MB and 300 pages. Synchronous calls stop at 10 MB and process only the first five pages.
  • Confidence is not correctness. A high score means the analyzer is sure what the page says. It cannot know the page is wrong, as invoice 3 shows.
  • Preview features move. Agentic mode, which reasons over a document for calculations and validation, is preview on 2026-06-01-preview and supports one input file per request.
  • Normalisation hides formatting. You get the canonical value, not the printed one. Keep the source location if an auditor needs to see what the page actually said.

On the brewhouse floor

A brewery receives a malt delivery note and a certificate of analysis with every load. The supplier's numbers for moisture and extract are printed in a table nobody retypes until something goes wrong. Run the certificate through Content Understanding, check each field's confidence and compare the extract value with the brewery's own specification. A certificate read with 0.95 confidence that shows extract below spec is not a reading problem. It is a quality conversation with the maltster. The pipeline should open it before the malt is milled.
