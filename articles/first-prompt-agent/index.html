Your first prompt agent: the Harbour Goods support agent

Build the Harbour Goods customer support agent as a prompt agent in the new Foundry portal. Write its instructions, test it against six questions with known answers, save it as version 1, change it and save version 2, then call the same agent from Python.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 1 Ankur Napa AgentsSDK

Short answer

A prompt agent is a model, instructions and optional tools, saved in Foundry as a versioned definition. Foundry runs it. You build it in the portal under Build, test it in the playground on the right and select Save to create a version. Versions are immutable. Every change you save becomes a new version you can compare and roll back to. In code, you refer to an agent as <agent_name>:<version>.

This step maps to the AI-103 area "Build agents by using Foundry": defining an agent's role, goals, conversation tracking and tool schemas.

What you will build

The Harbour Goods support agent. It answers order, delivery, returns and warranty questions for a six-store retailer. It has no tools yet. Everything it knows comes from its instructions, which carry the company's four policies. Tools come in the next article.

By the end you'll have:

  • An agent called harbour-goods-support with two saved versions.
  • Six test questions and the answers the agent should give.
  • A Python script that chats with the agent through the Responses API with keyless auth.

The policy facts come from first-prompt-agent.md, a short synthetic policy pack.

Before you start

  • A Foundry project in the new Foundry portal, not a classic hub-based project.
  • A chat model deployment in that project. This article uses a deployment named gpt-5.4-mini. Any current chat model works. If you don't have one, follow Deploy your first model and call it.
  • The Foundry User role on the project. Learn notes this role was previously named Azure AI User and the portal may still show the old name.
  • For the Python part: Python 3.10 or later, the Azure CLI and pip install "azure-ai-projects>=2.3.0" azure-identity.

Step 1: create the agent

  1. Sign in to the Foundry portal and open your project.
  2. In the top navigation, select Build. The list shows the agents in the project.
  3. Select the arrow next to New agent, then select Build an agent.
  4. In the Create an agent dialog, enter harbour-goods-support as the Agent name and select Create.

You can't rename an agent later. The name appears in traces, evaluations and code, so pick one you can live with.

The agent opens on the Playground tab. Configuration is on the left. The test chat is on the right.

Step 2: pick the model and write the instructions

  1. Under Model, select your gpt-5.4-mini deployment.
  2. Paste these instructions into Instructions:
You are the Harbour Goods customer support agent. Harbour Goods is a retailer
with six stores in India. You answer questions about orders, delivery, returns,
warranty and support hours. Answer in plain English, in three sentences or fewer.

Policies:
- Returns: accepted within 30 days of purchase with the receipt or order
  confirmation. Items must be unused. No receipt, no return.
- Delivery: 3 working days in metro cities, 5 working days elsewhere.
  Working days are Monday to Saturday.
- Electronics warranty: 12 months from delivery. Covers manufacturing faults,
  not accidental or water damage.
- Support hours: 9 AM to 9 PM IST, seven days a week.

Order IDs look like HG-240318-0042. You can't see order status yet. If someone
asks where an order is, ask for the order ID and say a colleague will check it.
Never invent an order status, a refund amount or a policy that isn't listed here.

The last line matters. Without a tool, the model has no way to see an order. Tell it so, or it will guess.

Step 3: test it in the playground

Ask each question in the chat pane. Compare with the expected answer.

#QuestionThe answer must say
1I bought a kettle 12 days ago and have the receipt. Can I return it?Yes, within 30 days, unused
2Can I return a jacket I bought 41 days ago?No, outside 30 days
3How long does delivery to Mumbai take?3 working days
4My headphones stopped working after 7 months. Covered?Yes, if it's a manufacturing fault, within 12 months
5Where is order HG-240318-0042?It can't see order status. A colleague will check
6Are you open at 10 PM?No, 9 AM to 9 PM IST

Question 5 is the one to watch. A good answer admits it can't see the order.

Step 4: save version 1

Select Save. This creates version 1.

Learn is explicit that you can test unsaved changes in the playground. To see conversation history, monitor the agent or run full evaluations, you have to save. Unsaved changes are lost if you leave the portal.

Step 5: change it and save version 2

Support wants the agent to quote the store code when a customer names a store. Add this to the end of the instructions:

Store codes: ST-003 Bengaluru South, ST-007 Chennai South, ST-011 Mumbai West,
ST-014 Pune West, ST-019 Delhi North, ST-022 Kolkata East. If a customer gives
a store code you don't recognise, say so and list the six valid codes.

Ask "I bought it at ST-099, can I return it there?". The agent should say ST-099 isn't a Harbour Goods store and list the six codes.

Select Save again. That's version 2.

Now use the version selector next to the agent name. Open version 1 and ask the ST-099 question again. It won't know about store codes. Learn lists three comparisons you can make between versions: the agent setup, the chat output for identical inputs and the YAML definition.

Step 6: call the agent from Python

Copy the project endpoint from the project Overview page. Sign in with az login, then run:

from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

# Format: https://<resource-name>.services.ai.azure.com/api/projects/<project-name>
FOUNDRY_PROJECT_ENDPOINT = "your_project_endpoint"
FOUNDRY_AGENT_NAME = "harbour-goods-support"

project = AIProjectClient(
    endpoint=FOUNDRY_PROJECT_ENDPOINT,
    credential=DefaultAzureCredential(),
)

# An OpenAI client bound to the agent
openai = project.get_openai_client(agent_name=FOUNDRY_AGENT_NAME)

# A conversation keeps history across turns
conversation = openai.conversations.create()

response = openai.responses.create(
    conversation=conversation.id,
    input="I bought a kettle 12 days ago and have the receipt. Can I return it?",
)
print(response.output_text)

response = openai.responses.create(
    conversation=conversation.id,
    input="And if it had been 41 days?",
)
print(response.output_text)

There's no API key anywhere. DefaultAzureCredential picks up your Azure CLI sign-in.

If you'd rather define the agent in code, project.agents.create_version() with a PromptAgentDefinition does the same as Save. Learn's quickstart shows it. That's the route for a CI/CD pipeline, covered later in CI/CD for agents.

Check it worked

  • The Build list shows harbour-goods-support.
  • The version selector shows versions 1 and 2.
  • Version 2 rejects ST-099 and lists the six valid codes. Version 1 doesn't mention store codes.
  • The Python script prints two answers. The first says yes, within 30 days. The second says no. The second answer only makes sense because the conversation kept the first turn.

Where this breaks

  • The agent invents an order status. Tighten the instruction and retest question 5. The real fix is a tool, which is the next article.
  • Long policies in the instructions. Four short policies fit. A forty-page returns manual doesn't. Move documents into file search, covered in Ground an agent in your files.
  • Forgetting to save. Conversation history, monitoring and full evaluations need a saved version.
  • Playground evaluations cost money. They're on by default in every Foundry project and billed as consumption. Turn them off in the metrics menu at the top of the playground if you're iterating fast.
  • Old code samples. The code here uses azure-ai-projects 2.x. It doesn't work with 1.x or the classic agents.
  • A 404 on an agent you created yesterday. Learn says to treat a 404 as terminal: the agent was deleted. Recreate it rather than retrying.

On the brewhouse floor

Brewery A's taproom staff ask the same five questions every shift: what's gluten-reduced, what's on the guest tap, how long a growler keeps. A prompt agent with those answers in its instructions handles it in an afternoon. When the head brewer changes the guest tap, someone edits the instructions and saves version 7. If version 7 starts recommending a keg that's already empty, the bar manager rolls back to version 6 before the evening rush.
