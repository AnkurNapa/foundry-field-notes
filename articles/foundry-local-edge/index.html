Foundry Local and the edge: run models on a laptop or offline site

When the network drops, a cloud agent stops answering. Foundry Local runs a small model on the device itself. Measure what your hardware can do, pick and pre-cache the right model variant, fall back cleanly between local and cloud. Then know the limits: single user, curated catalogue, no Foundry agent features on the device.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 3 Ankur Napa EdgeModelsArchitecture

Short answer

Foundry Local is an on-device runtime and SDK. It downloads a model from a curated catalogue, picks the variant that suits the hardware (CUDA on an NVIDIA GPU, a Qualcomm or AMD NPU, WebGPU, or CPU as the fallback) and runs inference in your application's process through ONNX Runtime. It adds about 20 MB to an app. No Azure subscription is needed. Prompts and outputs stay on the device. The network is used for the first model and execution provider downloads.

The limits decide whether it fits. Learn describes Foundry Local as built for one user at a time on a constrained device, not as a server. It runs a model, not Foundry Agent Service: file search, evaluations, tracing and versioned agents live in a cloud project. The CLI is in preview.

The symptom

Harbour Goods store ST-022 Kolkata East loses its internet link for a few hours most monsoons. The counter staff use the support agent from A chat app on your own data to answer returns and warranty questions. When the link drops, the page shows "The support agent is unavailable" and a queue forms. The ask from the store manager: keep answering the four standard policies with no connection, on the counter laptop. Then switch back to the cloud agent when the link returns.

Measure it

Do not pick a model from a blog post. Measure on the laptop that will run it.

1. Install the CLI and see what the hardware offers.

winget install Microsoft.FoundryLocal

On macOS with Apple silicon, use brew tap microsoft/foundrylocal then brew install foundrylocal. Then:

foundry --version
foundry model list --type chat
foundry model list --device gpu
foundry model list --device npu
foundry model info phi-4-mini

On first run Foundry Local downloads execution providers for the hardware before it shows the catalogue. An empty GPU or NPU list means the model will run on CPU.

2. Time it from code. The CLI is for exploration. The app will use the SDK, so measure through the SDK. This script follows Learn's Python quickstart and adds timers for load time, time to first token and streamed chunks per second.

pip install foundry-local-sdk-winml openai   # Windows; use foundry-local-sdk elsewhere
import sys
import time

from foundry_local_sdk import Configuration, FoundryLocalManager

ALIAS = sys.argv[1] if len(sys.argv) > 1 else "qwen2.5-0.5b"
PROMPT = ("A customer bought headphones 25 days ago and has the order ID "
          "but not the receipt. Under a 30 day returns policy that accepts "
          "a receipt or order ID, can they return them? Answer in 40 words.")

FoundryLocalManager.initialize(Configuration(app_name="hg_store_offline"))
manager = FoundryLocalManager.instance
manager.download_and_register_eps(progress_callback=lambda name, pct: None)

model = manager.catalog.get_model(ALIAS)
model.download(lambda progress: None)
start = time.perf_counter()
model.load()
loaded = time.perf_counter()

client = model.get_chat_client()
sent = time.perf_counter()
first, chunks = None, 0
for chunk in client.complete_streaming_chat([{"role": "user", "content": PROMPT}]):
    if chunk.choices and chunk.choices[0].delta.content:
        first = first or time.perf_counter()
        chunks += 1
done = time.perf_counter()
model.unload()

print(f"{ALIAS}: load {loaded - start:.1f} s, "
      f"first token {(first - sent) * 1000:.0f} ms, "
      f"{chunks / (done - first):.1f} chunks/s")

Run it for two or three candidate aliases, three times each, on the counter laptop with the store's other software open. Chunks per second is a proxy for tokens per second; the streaming API returns content deltas, not a token count.

3. Check the answer, not just the speed. The prompt has one right answer: yes, the order ID is enough. A fast model that says no is not a candidate.

Fix it

  1. Pick the smallest model that passes the answer check. Use an alias, not a full model ID, so Foundry Local picks the variant for the device. Learn's performance advice is to prefer GPU acceleration where available and to try more quantised variants, such as INT8 rather than FP16, when inference is slow.

  2. Pre-cache before the monsoon, not during it. Model downloads need the network. Download on the store's good days:

    foundry model download phi-4-mini
foundry cache list
foundry cache location

    If the system disk is small, move the cache with foundry cache cd <path>.

  3. Ship the policies with the app. There is no file search on the device. The four policies total under 300 words, so put them in the system message. For a larger library you would need your own local retrieval.

  4. Fall back in one place. Try the cloud agent with a short timeout. On a connection error, answer from the local model and label the reply "offline answer". The OpenAI-compatible API on both sides keeps the two code paths close.

  5. Stop competing workloads. Learn's troubleshooting advice is to stop any Foundry Toolkit for VS Code inference session before running Foundry Local and to watch memory during inference.

  6. Encrypt the disk if cached models were fine-tuned on sensitive data, as Learn's security guidance recommends.

Where this breaks

  • Not a server. Foundry Local is designed for a single user on the device. For many concurrent users, Learn points to server runtimes such as vLLM or Triton Inference Server.
  • Curated catalogue. Only models in the Foundry Local catalogue run, chosen to be small enough to distribute. Your cloud deployment model is not available locally.
  • No agent features. No versioned agents, file search, evaluations or traces on the device. The offline path answers from a prompt and loses citations.
  • Package confusion. The PyPI package foundry-local without -sdk is unrelated third-party software. Install foundry-local-sdk, or foundry-local-sdk-winml on Windows. Never install both.
  • Preview edges. The CLI is in preview. Foundry Local on Azure Local, for Kubernetes clusters at a site, is a separate preview product with its own requirements.
  • Platform. Windows, macOS on Apple silicon and Linux are supported. Intel NPUs on Windows need the Intel NPU driver.

On the brewhouse floor

Vineyards are where connections go to die. Winery C's harvest crew logs grape intake at a weighbridge two valleys from the nearest tower. A small local model on the weighbridge laptop can turn a spoken note ("bin 14, Shiraz, block 3, 412 kilos, some botrytis") into a clean intake record with no signal at all, then sync when the truck reaches the winery. The same limits apply: one user and one laptop. The full cellar agent still lives in the cloud.
