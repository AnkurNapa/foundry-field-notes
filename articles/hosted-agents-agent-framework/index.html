Hosted agents with Agent Framework: package and deploy with azd

Scaffold a hosted agent from the Agent Framework basic sample, turn it into the Harbour Goods support agent with an order lookup tool written in Python, test it locally, then deploy it to Foundry Agent Service with azd and invoke it from the command line.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa AgentsSDKCI/CD

Short answer

A hosted agent is your own agent code, run by Foundry. You write it with Agent Framework or another framework. Foundry builds it into a container, gives it a managed endpoint and a dedicated Microsoft Entra identity. It scales per session. Use it when the agent needs to call code you own, such as an order system.

The Azure Developer CLI does the packaging. Five commands cover the whole loop:

CommandWhat it does
azd ai agent initScaffolds an agent project from a sample manifest
azd provisionCreates the Azure resources in azure.yaml
azd ai agent runRuns the agent locally and opens the agent inspector
azd deployZips the source, uploads it, builds and deploys it in Foundry
azd ai agent invokeSends a prompt to the deployed agent

This step maps to the AI-103 skill area "Set up AI solutions in Foundry", specifically "Configure model and agent deployments". It also covers integrating custom functions as agent tools.

What you will build

The Harbour Goods support agent, rewritten as code. It gains one thing a prompt agent can't have: a Python function that looks up an order. In this article the function reads a small dictionary. In production it would call the order system.

You'll deploy it as hg-support-hosted and ask it about three orders from built-in-agent-tools.csv.

Before you start

  • An Azure subscription.
  • Foundry Project Manager at project scope if you use an existing project. To create a new project, Owner at resource group scope. Learn keeps a full matrix in the hosted agent permissions reference.
  • The Foundry Dev Pack, which installs the Azure Developer CLI azd 1.27.1 or later and the Foundry extensions. Run azd version to check.
  • Python 3.13 or later for the local run.
  • A region that supports hosted agents. Learn's list includes South India, Southeast Asia, Sweden Central, UK South and East US 2, among others.
  • A model deployment you can use, such as gpt-5.4-mini. The scaffold can create one.

Step 1: scaffold from the basic sample

Sign in, then run init in an empty folder:

azd auth login
mkdir hg-support-hosted && cd hg-support-hosted
azd ai agent init -m "https://github.com/microsoft-foundry/foundry-samples/blob/main/samples/python/hosted-agents/agent-framework/responses/01-basic/azure.yaml" --deploy-mode code

Answer the prompts:

  • Agent name: hg-support-hosted.
  • Foundry Project: create a new one or pick an existing one.
  • Tenant, Subscription and Location: your own. Pick a hosted agent region.
  • Model: the default gpt-5.4-mini, or another model you can access.
  • Model SKU: one with quota that isn't Batch, usually Standard or GlobalStandard.
  • Deployment capacity and Deployment name: the defaults are fine.

You should see AI agent definition added to your azd project successfully! Change into the new agent folder that init created.

Step 2: provision

azd provision

This creates whatever azure.yaml defines and you don't already have: the project, the model deployment, a container registry and Application Insights.

Step 3: make it the Harbour Goods agent

Open the sample's main.py and replace its contents with this. Keep the environment variable names the scaffold set up. The pattern is Learn's Agent Framework hosting sample with one tool added.

import os
from typing import Annotated

from agent_framework import Agent, tool
from agent_framework.foundry import FoundryChatClient
from agent_framework_foundry_hosting import ResponsesHostServer
from azure.identity import DefaultAzureCredential
from pydantic import Field

# Three hard-coded orders for the walkthrough. Replace with a call to the order system.
ORDERS = {
    "HG-260306-0028": ("ST-014", "Pune West", "Electronics", 11130, "In transit"),
    "HG-260304-0008": ("ST-011", "Mumbai West", "Kitchen", 2470, "Returned"),
    "HG-260313-0018": ("ST-099", "", "Electronics", 9410, "In transit"),
}

INSTRUCTIONS = """You are the Harbour Goods customer support agent.
Use lookup_order whenever a customer gives an order ID. Never guess a status.
Delivery takes 3 working days in metro cities and 5 elsewhere.
Returns are accepted within 30 days with a receipt.
Valid store codes are ST-003, ST-007, ST-011, ST-014, ST-019 and ST-022.
If an order carries any other store code, say the record needs checking."""


@tool(approval_mode="never_require")
def lookup_order(
    order_id: Annotated[str, Field(description="Harbour Goods order ID, such as HG-260306-0028.")],
) -> str:
    """Look up the store, category, value and status of a Harbour Goods order."""
    order = ORDERS.get(order_id.strip().upper())
    if order is None:
        return f"No order found with ID {order_id}."
    code, store, category, amount, status = order
    return f"{order_id}: store {code} {store}, {category}, INR {amount}, status {status}."


def main() -> None:
    client = FoundryChatClient(
        project_endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
        model=os.environ["AZURE_AI_MODEL_DEPLOYMENT_NAME"],
        credential=DefaultAzureCredential(),
    )
    agent = Agent(
        client=client,
        instructions=INSTRUCTIONS,
        tools=[lookup_order],
        # The hosting layer manages conversation history.
        default_options={"store": False},
    )
    ResponsesHostServer(agent).run()


if __name__ == "__main__":
    main()

approval_mode="never_require" is fine for a read-only lookup. A tool that changes something, such as creating a return, should require approval. That's Long-running agents and human approval.

Note what isn't here: no API key and no connection string. Locally, DefaultAzureCredential uses your sign-in. Deployed, the agent authenticates with its own Entra identity.

Step 4: test locally

azd ai agent run

This creates a virtual environment, installs dependencies, starts the agent with the startupCommand from azure.yaml and opens the agent inspector in your browser. The agent listens on http://localhost:8088.

Ask the three test questions in the inspector. The expected answers are in "Check it worked".

Step 5: deploy

azd deploy

azd packages the source as a zip file and uploads it. Foundry resolves dependencies, builds the image remotely and deploys version 1. The output prints two links: the agent playground in the portal and the agent endpoint.

The endpoint works straight away. Publishing isn't required for programmatic access. For the Responses protocol it is {project_endpoint}/agents/hg-support-hosted/endpoint/protocols/openai/responses.

Step 6: invoke and watch the logs

azd ai agent invoke "Where is order HG-260306-0028?"
azd ai agent monitor --follow

monitor --follow streams container logs while you send more prompts from a second terminal.

Check it worked

PromptThe answer must say
Where is order HG-260306-0028?In transit, Pune West, electronics, INR 11,130
Can I return order HG-260304-0008?It has already been returned
What's the status of HG-260313-0018?In transit, but ST-099 isn't a valid store, so the record needs checking
Where is HG-260101-0001?No order found. No invented status

Then open the playground link from step 5. The agent appears in the project's Build list. You can invoke, evaluate, monitor and publish it from the portal. You can't edit its logic there.

Where this breaks

  • Secrets in environment variables. Learn says don't put secrets in container images or environment variables. Use managed identity, connections and Key Vault. Environment variables are also immutable per version.
  • Expecting traffic splitting. An agent endpoint serves one version at a time with 100 per cent of traffic. Canary releases need a second agent.
  • Oversized sandboxes. CPU and memory describe one session, not the whole agent. Billing counts every active session, so oversizing multiplies by concurrency. The sizes are 0.5 vCPU with 1 GiB, 1 vCPU with 2 GiB and 2 vCPU with 4 GiB. Learn suggests raising the allocation only when sustained peaks pass about 70 per cent.
  • Idle sessions. The idle timeout defaults to 15 minutes and can be set from 2 to 60. Files under $HOME survive. A session is deleted after 30 days of inactivity.
  • azd ai agent init fails. Check azd version is 1.27.1 or later and azd ext show azure.ai.agents is 1.0.0-beta.4 or later.
  • Port 8088 already in use. The local run fails with connection refused. Stop the other process.
  • Windows on Arm. Some packages have no prebuilt arm64 wheels. Learn's workaround is to skip the local run and validate with azd deploy then azd ai agent invoke.
  • Private registries on older projects. Projects created before 25 June 2026 need the container registry reachable over its public endpoint.
  • azd down deletes more than you think. If azd created the project, azd down deletes its resource group and everything in it.

On the brewhouse floor

Brewery A's packaging lead wants to ask "how many cases of the pale ale did line 2 fill yesterday?" The answer lives in the filler's counter database, which no built-in tool can reach. A hosted agent holds a small Python function that queries it with the agent's own identity and read-only rights. When the filler's database moves, the function changes, a new version ships with azd deploy and the question still works on Monday.
