Built-in evaluators: what each one scores and when to use it

A working guide to Foundry's built-in evaluators: quality, RAG, agent and safety, what each one measures, the inputs it needs and its scale. Then prove it on a 24-row Harbour Goods dataset with six planted fabrications and three thin answers.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa EvaluationSafetySDK

Short answer

Foundry ships five families of built-in evaluators: general purpose (how the text reads), RAG (does it stick to the source and cover the facts), agent (did it understand, follow its rules and use tools well), risk and safety (harmful content and agent risks) and textual similarity (overlap with a reference answer).

Pick by failure, not by count. For a support agent that must quote policy correctly, Groundedness and Response Completeness do the heavy lifting. The four content safety evaluators are the floor for anything customer-facing. Many agent evaluators are still in preview, so date every score you keep.

This step maps to the AI-103 skill area "Plan and manage an Azure AI solution", specifically applying responsible AI instrumentation with evaluators and safety evaluations. It also covers "Evaluate models and apps, including detecting fabrications, relevance, quality and safety".

What you will build

A reference you can keep open and one dataset evaluation that proves the evaluators catch what they claim to catch. The dataset is built-in-evaluators.jsonl: 24 Harbour Goods questions, each with the policy text as context, a pre-written response and a ground_truth. A planted column tells you what is wrong with each row:

plantedRowsWhat is wrong.
none15Nothing. The response matches the policy.
ungrounded6A made-up fact: 45-day returns, no receipt needed, 2-day Delhi delivery, a 24-month laptop warranty, accidental damage cover, round-the-clock support.
incomplete3True but thin: "Bring the item back", "It is quick", "Support is open in the daytime".

The rows cover returns (7), delivery (7), warranty (6) and support hours (4). The responses are pre-written, so no agent runs and the scores reflect only the evaluators.

The evaluators, family by family

Names are as Learn lists them in October 2026. The SDK name is builtin. plus the snake-case name, such as builtin.groundedness.

General purpose

EvaluatorScoresNeedsScale
CoherenceLogical flow and consistencyquery, response, judge model1 to 5, pass at 3.
FluencyGrammar and readabilityresponse, judge model1 to 5, pass at 3.

Hygiene only. Neither tells you whether the answer is true.

RAG

EvaluatorScoresNeedsScale
GroundednessDoes the response stay inside the context, with nothing invented? This is precision.response, context; query optional1 to 5, pass at 3.
Groundedness Pro (preview)Strict consistency with the context, using Azure AI Content Safetyquery, response, context; no judge modelPass or fail.
RelevanceDoes the response address the query?query, response1 to 5, pass at 3.
Response Completeness (preview)Does the response cover the facts in the ground truth? This is recall.ground_truth, response1 to 5, pass at 3.
RetrievalAre the retrieved chunks relevant to the query?query, context1 to 5, pass at 3.
Document RetrievalSearch quality against labelled relevance judgementsretrieval_ground_truth, retrieved_documents; no judge modelFidelity, NDCG, XDCG, max relevance, holes.

Learn's own framing is the one to remember: groundedness is precision, completeness is recall. You want both.

Two warnings from Learn. Tool evaluators and Groundedness have limited support when the conversation includes Azure AI Search, Bing grounding, SharePoint grounding, Code Interpreter, Fabric data agent or web search calls. And the Quality Grader is deprecated on the agent evaluators page and can no longer run, although the overview reference still lists it.

Risk and safety

EvaluatorDetectsOutput
Violence, Sexual, Self-Harm, Hate and UnfairnessHarmful contentSeverity 0 to 7. Passes at or below the threshold, default 3.
Protected MaterialsCopyrighted text such as lyrics or articlesPass or fail.
Indirect Attack (XPIA)A response that obeyed instructions hidden in retrieved contentPass or fail.
Code VulnerabilityInsecure generated codePass or fail.
Ungrounded AttributesUnfounded inferences about a person's emotional state or protected classTrue or false.
Prohibited Actions (preview), Sensitive Data Leakage (preview)Agent-only risks. Agent targets only, not datasets.Pass or fail.

Safety evaluators run on Microsoft-hosted models and do not take a deployment_name. They run only in listed regions. In October 2026 none of those is in India.

Textual similarity

Similarity, F1 Score, BLEU, GLEU, ROUGE and METEOR compare the response with a ground truth. They suit translation. A correct support answer worded differently scores low.

Before you start

  • A Foundry project, the Foundry User role and a judge model such as gpt-5.4-mini.
  • A project in a region that supports risk and safety evaluators, such as Sweden Central or East US 2. Groundedness Pro runs only in East US 2 and Sweden Central.
  • pip install "azure-ai-projects>=2.2.0" azure-identity

Step 1: upload the dataset

import os
from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import TestingCriterionAzureAIEvaluator
from openai.types.eval_create_params import DataSourceConfigCustom
from openai.types.evals.create_eval_jsonl_run_data_source_param import (
    CreateEvalJSONLRunDataSourceParam,
    SourceFileID,
)

project_client = AIProjectClient(
    endpoint=os.environ["AZURE_AI_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)
openai_client = project_client.get_openai_client()
judge = os.environ["AZURE_AI_MODEL_DEPLOYMENT_NAME"]

data_id = project_client.datasets.upload_file(
    name="hg-builtin-evaluators",
    version="1",
    file_path="./built-in-evaluators.jsonl",
).id

Step 2: pick the evaluators

Six evaluators, each mapped to the columns it needs. Every AI-assisted one gets the judge deployment.

def criterion(name, evaluator, mapping, needs_judge=True):
    # Safety evaluators run on hosted models and take no judge deployment.
    extra = {"initialization_parameters": {"deployment_name": judge}} if needs_judge else {}
    return TestingCriterionAzureAIEvaluator(
        type="azure_ai_evaluator",
        name=name,
        evaluator_name=evaluator,
        data_mapping=mapping,
        **extra,
    )

qr = {"query": "{{item.query}}", "response": "{{item.response}}"}

testing_criteria = [
    criterion("groundedness", "builtin.groundedness",
              {"query": "{{item.query}}", "response": "{{item.response}}", "context": "{{item.context}}"}),
    criterion("response_completeness", "builtin.response_completeness",
              {"ground_truth": "{{item.ground_truth}}", "response": "{{item.response}}"}),
    criterion("relevance", "builtin.relevance", qr),
    criterion("coherence", "builtin.coherence", qr),
    criterion("violence", "builtin.violence", qr, needs_judge=False),
    criterion("hate_unfairness", "builtin.hate_unfairness", qr, needs_judge=False),
]

Step 3: create and run the evaluation

eval_object = openai_client.evals.create(
    name="hg-builtin-evaluators",
    data_source_config=DataSourceConfigCustom(
        type="custom",
        item_schema={
            "type": "object",
            "properties": {
                "query": {"type": "string"},
                "context": {"type": "string"},
                "response": {"type": "string"},
                "ground_truth": {"type": "string"},
                "planted": {"type": "string"},
            },
            "required": ["query", "context", "response", "ground_truth"],
        },
    ),
    testing_criteria=testing_criteria,
)

eval_run = openai_client.evals.runs.create(
    eval_id=eval_object.id,
    name="hg-builtin-evaluators-run-1",
    data_source=CreateEvalJSONLRunDataSourceParam(
        type="jsonl",
        source=SourceFileID(type="file_id", id=data_id),
    ),
)
print(eval_run.id)

Poll with openai_client.evals.runs.retrieve(run_id=..., eval_id=...) until the status is completed, as in Run your first evaluation. Then open the run under Evaluation in the portal.

Check it worked

The planted column is your answer key. In the run details, compare each row's result with it.

EvaluatorExpected on the 24 rows.
groundednessFails the 6 ungrounded rows. Passes the 15 none rows. The 3 incomplete rows say nothing false, so they can pass.
response_completenessFails the 3 incomplete rows. Most of the 6 ungrounded rows fail too, because a wrong number does not cover the right one.
relevancePasses most rows. All 24 responses are on topic, which is the point: relevance alone cannot catch a fabrication.
coherencePasses most rows, including the fabrications. Fluent nonsense is still fluent.
violence, hate_unfairness24 passes, severity 0 or 1.

If groundedness passes a planted row, open the reason. A small judge model can miss a wrong number. Rerun with a stronger judge before you build a gate on it.

Where this breaks

  • Parameter name drift. Learn's agent evaluation pages pass the judge as deployment_name. Some dataset samples use model. If a run errors on initialisation, try the other key.
  • Preview churn. Intent Resolution, Task Adherence, Task Completion, Customer Satisfaction, Response Completeness, Groundedness Pro and the composite evaluators are in preview. Thresholds and prompts can move.
  • Composite judge models. Learn recommends a model from the GPT-5.6 family as judge for Output Quality and Tool Use Quality. Check that one is deployed before you rely on the composites.
  • Very short answers. Learn notes that Coherence and Fluency scores can be unreliable for responses under about 20 tokens. The three incomplete rows are that short on purpose, so read their reasons rather than trusting the number. Both evaluators also support English responses only.
  • Missing fields. Groundedness without context has to infer context from tool calls, which works only for agent targets. On a dataset, map context explicitly.
  • Safety evaluator regions. A project in Central India runs the quality evaluators and errors on the safety ones.

On the brewhouse floor

Winery A has an assistant that answers trade buyers from its tech sheets: residual sugar, alcohol by volume, closure type, case configuration. A seeded dataset with a few planted errors, such as 13.5 per cent alcohol where the sheet says 12.5, tells the export manager whether groundedness actually catches a wrong number on that kind of document. Relevance will happily pass the wrong figure, because it is on topic. Seed the errors yourself, so you know the answer key before you trust the score.
