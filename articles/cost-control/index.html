Cost control: forecast, cap and charge back Foundry tokens

A month of token data shows one agent burned 71 percent of the spend and a single bad day used 4.5 times its normal volume. Measure it, cap it per project with AI Gateway, then charge it back by project tag.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 3 Ankur Napa CostGovernanceObservability

Short answer

Foundry bills tokens. The bill follows the busiest project, not the average one. Cost control has three jobs. Forecast from measured token counts multiplied by the rates for your model, region and deployment type. Cap with token limits per project through AI Gateway, because Azure OpenAI has no hard spending limit of its own. Charge back with the project tag Foundry adds to usage, so each team sees its own share.

A note on prices. When this article was written, on 12 October 2026, the Azure OpenAI pricing page rendered its rate cells blank in a text fetch. So this article quotes no per-token prices. Take rates from the Azure pricing calculator for your region and deployment type. Expect them to vary by both. The same page states that the Batch API returns completions within 24 hours at a 50 percent discount on Global Standard pricing.

For AI-103, this covers "Manage quotas, scaling, rate limits and cost footprints for model and agent workloads".

The symptom

Harbour Goods runs three projects on one Foundry resource, all on a Global Standard gpt-5.4-mini deployment: the support agent, catalogue enrichment and invoice extraction. Finance asks two questions after the September invoice. Which team spent it? Why was one week so much higher than the others?

The token data for the month is in cost-control.csv: 90 rows, one per project per day, with input, cached input and output tokens.

Measure it

1. In the Foundry portal. Select Operate in the upper-right menu, then Overview, pick the projects and a date range. The Estimated cost tile shows agent cost estimates. For one deployment, select Build > Models, select the model and open its Monitor tab. Use these estimates for near-real-time watching, not for reconciliation. They exclude discounts and provisioned throughput.

2. In Cost Management. In the Azure portal, open the resource group and select Cost analysis. Set Group by to Meter to see input and output meters per model. To split by project, open the Foundry resource's Cost analysis, select Add filter > Tag and choose project. Foundry tags usage with the project automatically. This project-level attribution is in preview and covers Models sold by Azure only, not Marketplace models.

3. From the token export. This script totals the CSV per project and turns tokens into money with rates you supply.

import csv
from collections import defaultdict

# Rates per 1 million tokens for your model, region and deployment type.
# Fill these from the Azure pricing calculator. Left at zero on purpose.
RATE_INPUT = 0.0
RATE_CACHED_INPUT = 0.0
RATE_OUTPUT = 0.0

totals = defaultdict(lambda: {"input": 0, "cached": 0, "output": 0})
daily = defaultdict(int)
with open("cost-control.csv", newline="") as f:
    for row in csv.DictReader(f):
        t = totals[row["project"]]
        t["input"] += int(row["input_tokens"])
        t["cached"] += int(row["cached_input_tokens"])
        t["output"] += int(row["output_tokens"])
        daily[(row["project"], row["date"])] += int(row["input_tokens"]) + int(row["output_tokens"])

grand = sum(t["input"] + t["output"] for t in totals.values())
for project, t in totals.items():
    uncached = t["input"] - t["cached"]
    cost = (uncached * RATE_INPUT + t["cached"] * RATE_CACHED_INPUT + t["output"] * RATE_OUTPUT) / 1_000_000
    share = 100 * (t["input"] + t["output"]) / grand
    print(f"{project:<18} in={t['input']:>12,} cached={t['cached']:>12,} out={t['output']:>11,} share={share:5.1f}% cost={cost:,.2f}")

worst = max(daily.items(), key=lambda kv: kv[1])
print("busiest day:", worst)

That's 94,104,351 tokens in the month. The busiest single day was the support agent on 17 September at 9,241,462 tokens. Its median day was 2,052,012. A change to the agent's instructions on the 16th made it call a tool in a loop for some conversations. It was rolled back on the 18th.

Fix it

Forecast. Monthly cost is (uncached input × input rate + cached input × cached rate + output × output rate) ÷ 1,000,000, per deployment. Use the measured split, not a guess. At Harbour Goods, 35 percent of input tokens were cached, which matters because cached input is metered separately. Build the estimate in the pricing calculator, run representative traffic, then group Cost Management by Resource and Meter and compare. Learn suggests updating budgets only after one full billing cycle of trend.

Cap. Put the resource behind AI Gateway and give each project its own limits.

  1. In Microsoft Foundry, select Manage > AI Gateway and select the gateway. Creating one needs an API Management instance. Adding a project needs API Management Service Contributor or Owner on it.
  2. Add the three projects to the gateway. New projects join by default. Existing ones need Add project to gateway.
  3. Select Token management > + Set limit. Pick the project and deployment. Set a tokens-per-minute limit.
  4. Set a total token quota for a period. Harbour Goods chose a daily quota of 3,000,000 tokens for the support agent, about 1.18 times its busiest normal day.

A request over the TPM limit gets 429 Too Many Requests. A request over the period quota gets 403 Forbidden. Concurrent requests can overshoot briefly before responses finish.

Alert. In Cost Management, create a budget on the resource group with warning and critical thresholds. Budgets alert, they don't stop spending. To act automatically, wire the alert to an action group, which takes custom work.

Shift what can wait. Catalogue enrichment runs overnight and nobody reads it until morning. Move it to the Batch API for the 50 percent discount on Global Standard pricing, or look at Flex processing for delay-tolerant work.

Charge back. Each month, export Cost Management data to a storage account and split it by the project tag. Support, catalogue and invoices each see their own line.

Prove it

Replay September with the new cap.

The cap didn't change a normal day. It limited one bad day. The cost of that limit was real: on the 17th, support customers would have seen errors once the quota ran out. So the cap is a backstop, not the plan. The budget alert and a daily look at the Monitor tab are meant to catch a loop before the cap bites.

Where this breaks

  • No hard limit on Azure OpenAI. Budgets warn. Only gateway quotas and deployment TPM limits stop traffic.
  • The gateway is a new hop. Check API Management's region against the resource. A private Foundry also needs a private gateway, which you configure in API Management.
  • Tag gaps. Project attribution covers Models sold by Azure. Partner models bought through Marketplace appear under the resource group with their own meters.
  • Estimates aren't invoices. Portal estimates skip discounts and provisioned throughput. Reconcile with invoiced charges.
  • Hidden costs. Monitoring, logs, AI Search and storage are billed on their own meters and don't show when you scope to the Foundry resource.
  • Fine-tuned models. They bill hourly hosting while deployed, even when idle. Remove what you don't use.

On the brewhouse floor

Brewery A's sales assistant and its brewing log summariser share one Foundry resource. The monthly bill landed as one line. With the project tag, the sales team sees its own share and the brewhouse sees its own. A daily token quota on the summariser stops a stuck loop over the FV-03 log from spending a week's budget overnight. The brewer still reads the log. The quota just stops the model reading it four thousand times.
