Retrieval quality: fix bad answers with chunking, hybrid and reranking

The Harbour Goods agent quotes the returns policy when customers ask about warranty. Build a 20-question golden set, score three retrieval set-ups on hit rate and mean reciprocal rank, then fix it with section chunks, a title prefix, hybrid search and the semantic ranker. Includes the trap where the worse set-up looks better on paper.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 3 Ankur Napa SearchKnowledgeEvaluation

Short answer

Most bad RAG answers are retrieval failures. The model writes a fluent answer from the wrong passage. Nobody can tell until a customer acts on it. Fix retrieval before you touch the prompt.

The loop is short. Write a golden set of real questions, each labelled with the passage that answers it. Score retrieval on its own, before any model writes a word. Change one thing. Score again. Learn's retrieval guidance gives you the levers: chunk by structure rather than by character count, put the document title on every chunk, run hybrid search so exact strings and meaning both count and let the semantic ranker reorder the top 50.

For AI-103 this is Configure semantic search, hybrid search and vector search for grounding and Monitor data ingestion quality, search index health and relevance performance.

The symptom

Harbour Goods support leads send three screenshots in one week:

  • "My kettle stopped heating after two months." The agent replied that returns close after 30 days and stopped there. It never mentioned the 12-month warranty.
  • "What is the warranty on a sofa?" The agent said 12 months. Furniture is 6.
  • "What does HG-POL-DEL say about tracking?" The agent summarised the returns policy.

All three answers cite a real document. The citations are the giveaway: they point at the right file for the wrong reason, or at the wrong file entirely.

The index behind the agent is the one from Your first Azure AI Search index. The wizard's fixed chunking splits text into pages of up to 2,000 characters. Every Harbour Goods policy is shorter than that, so each policy became one chunk. A warranty question has to compete with the whole returns policy as a single blob. The model gets 2,000 characters to search through by itself.

Measure it

Start with the golden set: retrieval-quality-golden.jsonl. It holds 20 questions written the way customers write, each labelled with the policy sections that answer it, such as R2 or W1. Some questions have two correct sections. Some deliberately share no words with the answer ("send back a blender I've had for five weeks").

Three numbers are enough to start:

MetricQuestion it answers
Hit@1How often is the top result a correct section?
Hit@3How often is a correct section somewhere in the top three?
MRR@3Mean reciprocal rank: 1 if the first correct result is at rank 1, 0.5 at rank 2, 0.33 at rank 3, 0 if missing

This script runs any search set-up against the golden set. A result's label comes from its title. Whole-document results get a document letter (R, D or W) and count as a hit if any relevant section is in that document, which is generous on purpose.

import json
import re

from azure.identity import DefaultAzureCredential
from azure.search.documents import SearchClient
from azure.search.documents.models import VectorizableTextQuery

ENDPOINT = "https://<your-search>.search.windows.net"
cred = DefaultAzureCredential()
gold = [json.loads(line) for line in open("retrieval-quality-golden.jsonl")]

def label(title):
    m = re.search(r"\b([RDW]\d)\b", title)
    if m:
        return m.group(1)
    return {"returns": "R", "delivery": "D", "warranty": "W"}[re.search(r"returns|delivery|warranty", title).group(0)]

def score(run):
    hit1 = hit3 = rr = 0
    for g in gold:
        labels = [label(r["title"]) for r in run(g["question"])][:3]
        ranks = [i for i, x in enumerate(labels, 1) if any(rel.startswith(x) for rel in g["relevant"])]
        hit1 += bool(ranks and ranks[0] == 1)
        hit3 += bool(ranks)
        rr += 1 / ranks[0] if ranks else 0
    n = len(gold)
    return round(hit1 / n, 2), round(hit3 / n, 2), round(rr / n, 3)

def vector_only(index):
    client = SearchClient(ENDPOINT, index, cred)
    def run(q):
        vq = VectorizableTextQuery(text=q, k_nearest_neighbors=3, fields="text_vector")
        return client.search(search_text=None, vector_queries=[vq], select=["title"], top=3)
    return run

print("A vector, whole documents:", score(vector_only("hg-policies")))

If you want Foundry to compute the scores, the Document Retrieval evaluator takes the same idea, a list of labelled relevant documents and a list of retrieved documents with scores. It returns Fidelity, NDCG, XDCG, max relevance and holes. Learn recommends it when retrieval is the bottleneck and you have relevance labels. The Retrieval evaluator works without labels by using an LLM judge, which is useful for production traffic you have not labelled.

Fix it

Three changes, in order of how much they usually buy.

1. Chunk by structure, with the title on every chunk. Learn's chunking guide lists variable-sized chunks based on headings for Markdown and recommends adding the document title to chunks from the middle of a document so they keep their context. The policies already have numbered ## sections, so split on them and prefix each one with the policy name and ID:

from pathlib import Path

out = Path("sections")
out.mkdir(exist_ok=True)
for path in Path("policies").glob("*.md"):
    head, *sections = path.read_text().split("\n## ")
    title, policy_line = head.strip().splitlines()[0], head.strip().splitlines()[-1]
    for sec in sections:
        sid = sec.split(".", 1)[0]
        name = path.stem.replace("ground-agent-in-files-", "")
        (out / f"{sid}-{name}.md").write_text(f"{title}\n{policy_line}\n\n## {sec.strip()}\n")

That gives 18 files, R1 to R7, D1 to D6 and W1 to W5. Upload them to a new container and run the Import data wizard again with the prefix hg-sections. Each file is well under 2,000 characters, so each section becomes exactly one chunk with its policy ID attached. The HG-POL-DEL question now has something to match.

2. Go hybrid. Keyword search finds HG-POL-DEL, UPI and INR 150. Vector search finds "my parcel turned up late". Hybrid runs both and merges the lists with Reciprocal Rank Fusion.

3. Add the semantic ranker. It reranks the top 50 results with a language model and scores each from 0 to 4. Learn's hybrid query guide says to make k and the text recall add up to at least 50 when you use it, then cut the final list with top:

def hybrid_semantic(index, semantic_config):
    client = SearchClient(ENDPOINT, index, cred)
    def run(q):
        vq = VectorizableTextQuery(text=q, k_nearest_neighbors=50, fields="text_vector")
        return client.search(
            search_text=q,
            vector_queries=[vq],
            query_type="semantic",
            semantic_configuration_name=semantic_config,
            select=["title"],
            top=3,
        )
    return run

print("B vector, sections:", score(vector_only("hg-sections")))
print("C hybrid + semantic, sections:", score(hybrid_semantic("hg-sections", "<semantic-config-name>")))

Find the semantic configuration name on the index's Semantic configurations tab. The wizard names it from your prefix.

Prove it

The table below scores a recorded run kept in retrieval-quality-runs.csv. It is synthetic, written to show the pattern you are looking for. The numbers were computed from that file with the same scoring rules. Your own run against a live index will produce different numbers. Rerun the script and replace these with yours.

Set-upHit@1Hit@3MRR@3
A: vector, one chunk per policy0.801.000.900
B: vector, section chunks0.650.950.792
C: hybrid + semantic ranker, section chunks0.951.000.975

Read row A carefully. It looks fine. It is also the set-up that produced the complaints. A hit there means "the right document is somewhere in a 2,000-character blob". Three of its four first-place misses are warranty questions ranked under the returns policy. The fourth is the policy code question. Those are the screenshots. Hit@3 is 1.00 because there are only three documents to choose from.

Row B is the honest version of A. Section chunks expose ranking errors that whole documents hide. Vector search alone puts the refund timing section above the no-receipt section and the general delivery times above the metro list. It misses the tracking section outright.

Row C fixes the ranking. The one first-place miss left ranks warranty claims (W4) above repairs (W2) for "who repairs my mixer", with W2 second. Both are warranty sections, so the answer is still right.

Then check the answers, not just the retrieval. Rerun the three screenshot questions through the agent and score them with the Groundedness evaluator. Retrieval that improves while groundedness does not means the instructions are the next problem.

Where this breaks

  • A golden set nobody updates. Questions drift. Add every complaint screenshot to the golden set with its correct section. The set gets better at catching the next one.
  • Generous labels hide failures. Counting a whole document as a hit, as row A does, flatters big chunks. Score at the level the model reads.
  • Over-splitting. Sections of two sentences lose context. Learn's starting point for fixed-size chunks is 512 tokens with 25 per cent overlap. Use structure when the documents have it and size limits when they do not.
  • Semantic ranker inputs. It reads at most about 2,000 tokens per result, with 128 for the title. Long chunks get trimmed before they are scored.
  • Scoring profiles and semantic ranking fight. The ranker can erase a freshness boost unless the semantic configuration's rankingOrder uses the boosted score.
  • Cost. The semantic ranker is billable. Agentic retrieval bills by tokens. Measure whether the gain is worth it per question, not per demo.

On the brewhouse floor

A café chain's kitchen assistant answers "how long can cooked rice sit in the hot hold?" from a food safety manual. Indexed as whole chapters, it kept quoting the chilled storage section, because both chapters talk about time and temperature. Split by heading, with the chapter title on every chunk, the hot-hold section came first. A golden set of 30 questions the head chef actually asks took an afternoon to write. It is the only reason anyone knew the first version was wrong before an inspector did.
