Trace an agent run in Microsoft Foundry

Connect Application Insights, ask the Harbour Goods support agent one awkward question and follow it span by span: the agent invocation, the model call, any tool call and the tokens each one spent. Then add client-side spans for your own code with OpenTelemetry.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 1 Ankur Napa ObservabilityAgentsSDK

Short answer

An evaluation tells you a reply was wrong. A trace tells you why. Foundry records server-side traces for prompt agents and hosted agents as soon as the project is connected to an Application Insights resource. No code changes are needed and traces appear within minutes. Each trace is a tree of spans: the agent invocation at the top, model calls and tool executions underneath, each with its timing, inputs, outputs and token counts. The portal keeps 90 days of traces on the Traces tab. When you need your own application code in the same picture, add client-side tracing with OpenTelemetry and the Foundry SDK.

Tracing is generally available for prompt and hosted agents. Workflow and external agents are in preview. Client-side GenAI tracing in the SDK is an experimental preview you must opt in to.

This step maps to the AI-103 skill area "Implement generative AI and agentic solutions", specifically setting up observability with tracing, token analytics and latency breakdowns.

What you will build

  • An Application Insights resource connected to the Foundry project.
  • One traced run of the Harbour Goods support agent, read span by span in the portal.
  • The same question asked from Python, with a custom span around your own store-code check, exported to the same Application Insights resource.

The question is row 8 from the first evaluation test set: "My order to Chennai was placed 4 working days ago and has not arrived. Is that late?" The right answer is yes, because Chennai is a metro city with a 3 working day promise. It is a good question to trace because the agent has to apply a rule, not just recite one.

Before you start

  • The harbour-goods-support prompt agent from Run your first evaluation. If it has the file search tool and the policy documents from Ground an agent in your files, you will also see a tool span. Without a tool you still see the agent and model spans.
  • An Application Insights resource, or the rights to create one.
  • The Log Analytics Reader role on that Application Insights resource, so you can query telemetry. If the underlying Log Analytics tables are protected, you also need Privileged Monitoring Data Reader.
  • For the Python part: Python 3.10 or later, azure-ai-projects 2.0.0 or later and Contributor or higher on the project.

Step 1: connect Application Insights

  1. Sign in to the Foundry portal with the New Foundry toggle on and open the project.
  2. In the left navigation, select Agents, then select Traces at the top.
  3. On the right, select Connect. Pick an existing Application Insights resource and select Connect, or select Create new and complete the wizard.
  4. Wait for the confirmation message.

If there is no Connect button, select Manage in the upper right, then Project details > Connected resources > Add connection > Application Insights.

Server-side tracing is now on for every agent in the project.

Step 2: grant read access

Connecting the resource does not let people read it. In the Azure portal, open the Application Insights resource, select Access control (IAM) and assign Log Analytics Reader to the people who debug agents. Use a Microsoft Entra group rather than individual users. Trace data can hold customer messages, so treat this role like access to production logs.

Step 3: make one traced run

  1. Open harbour-goods-support and select the Playground tab.
  2. Ask: My order to Chennai was placed 4 working days ago and has not arrived. Is that late?
  3. Note the reply. A good one says yes, apologises and offers to escalate.
  4. Wait two to five minutes. Learn gives that as the usual delay before a trace shows up.

Step 4: read the trace

  1. Go back to Agents > Traces. A new row appears with a timestamp, duration and status.
  2. Select it. The trace opens as a tree of spans in the order they ran.
  3. Read it from the top. Foundry follows the OpenTelemetry GenAI semantic conventions, so the span names are standard:
Span or attributeWhat it tells you.
invoke_agentThe whole agent run: start, end and total duration.
A model call spanOne request to the model deployment, with input and output tokens. An agent that thinks twice shows two.
execute_toolOne tool execution, such as file search. Shown only if the agent has tools.
gen_ai.tool.call.argumentsWhat the agent passed to the tool. This is where a wrong order ID shows up.
gen_ai.tool.call.resultWhat the tool sent back. Compare it with the final reply.
  1. Check three things: which span took the longest, how many tokens the model calls used in total and whether the final reply matches what the tool returned.
  2. To see the whole conversation, search the Traces page by the Response ID or Trace ID, then select the Conversation ID. The conversation view shows the history, response tokens, the ordered run steps and tool calls and the inputs and outputs between user and agent.

The OpenTelemetry GenAI conventions have Development status upstream. Attribute names can change in future releases, so do not hard-code them into alerts without a test.

Step 5: add client-side spans from Python

Server-side traces stop at the agent. If your app checks the store code before it calls the agent, that check is invisible until you trace it yourself. This is Learn's client-side sample with one custom function added. It creates a throwaway agent version so it does not touch your real one.

pip install azure-ai-projects azure-identity opentelemetry-sdk azure-core-tracing-opentelemetry azure-monitor-opentelemetry
import os

os.environ["AZURE_EXPERIMENTAL_ENABLE_GENAI_TRACING"] = "true"

from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import PromptAgentDefinition
from azure.ai.projects.telemetry import trace_function
from azure.identity import DefaultAzureCredential
from azure.monitor.opentelemetry import configure_azure_monitor
from opentelemetry import trace

VALID_STORES = {"ST-003", "ST-007", "ST-011", "ST-014", "ST-019", "ST-022"}

@trace_function("check-store-code")
def check_store_code(code: str) -> bool:
    return code in VALID_STORES

endpoint = os.environ["FOUNDRY_PROJECT_ENDPOINT"]

with (
    DefaultAzureCredential() as credential,
    AIProjectClient(endpoint=endpoint, credential=credential) as project,
):
    connection_string = project.telemetry.get_application_insights_connection_string()
    configure_azure_monitor(connection_string=connection_string)
    tracer = trace.get_tracer(__name__)

    with tracer.start_as_current_span("hg-support-chennai-question"):
        check_store_code("ST-007")
        with project.get_openai_client() as openai:
            agent = project.agents.create_version(
                agent_name="hg-support-trace-demo",
                definition=PromptAgentDefinition(
                    model=os.environ["FOUNDRY_MODEL_NAME"],
                    instructions=(
                        "You are the Harbour Goods support agent. Standard delivery is "
                        "3 working days in metro cities including Chennai. Elsewhere it is 5."
                    ),
                ),
            )
            conversation = openai.conversations.create()
            response = openai.responses.create(
                conversation=conversation.id,
                extra_body={"agent_reference": {"name": agent.name, "id": agent.id, "type": "agent_reference"}},
                input="My order to Chennai was placed 4 working days ago and has not arrived. Is that late?",
            )
            print(response.output_text)

            openai.conversations.delete(conversation_id=conversation.id)
            project.agents.delete_version(agent_name=agent.name, agent_version=agent.version)

Points that trip people up:

  • The environment variable must be set before instrumentation starts. Without it nothing is traced and a warning is logged.
  • Pass both name and id in agent_reference. Learn says that is what ties client traces to the agent in the portal.
  • Message content is not recorded by default. OTEL_INSTRUMENTATION_GENAI_CAPTURE_MESSAGE_CONTENT=true turns it on. Keep that to development.
  • @trace_function always records the function's parameters and return value, whatever the content setting says. Never decorate a function that takes a phone number or a payment reference.

Where this breaks

  • No traces at all. Usually no connected resource, no recent traffic or ingestion delay. Confirm the connection, run the agent again and refresh after a few minutes.
  • Authorisation errors. Missing Log Analytics Reader, or missing Privileged Monitoring Data Reader on protected tables.
  • Client spans not joined to server spans. In Python, get the OpenAI client from get_openai_client() after instrumentation starts. Trace context propagation is on by default when tracing is on.
  • Sensitive data in telemetry. Traces can hold user input, model output and tool arguments. Redact before it reaches a span and apply the same retention and access rules as other production logs.
  • Retention and cost. Retention, sampling and billing follow your Application Insights and Log Analytics settings, not Foundry's. The portal view stops at 90 days.

On the brewhouse floor

Distillery A runs an assistant that answers warehouse questions: which casks in Rack 4 are due for sampling and what the last strength reading was. A trace shows whether a wrong answer came from the model misreading the question, or from the lookup tool returning the reading for the wrong cask number. Those are different fixes, one in the instructions and one in the data. Without the trace both look like "the AI got it wrong" and someone rewrites the prompt for a bug in the tool.
