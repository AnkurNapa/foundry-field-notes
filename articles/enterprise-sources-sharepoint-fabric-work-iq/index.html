Enterprise sources: SharePoint, Fabric and Work IQ for Foundry agents

Ground one Harbour Goods agent in policies that live in SharePoint and sales numbers that live in Microsoft Fabric, without exporting either. Covers the SharePoint tool, the Fabric data agent tool, Fabric IQ, OneLake as a Foundry IQ knowledge source and Work IQ, with the identity rule that runs through all of them.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa KnowledgeFabricToolsSecurity

Short answer

Company knowledge already has homes: policies in SharePoint, sales and stock in Microsoft Fabric, email and meetings in Microsoft 365. Foundry lets an agent reach each one where it lives, so you do not build a second copy that drifts and leaks permissions.

There are two patterns. The difference matters.

PatternHow it worksCopies data?Examples
Remote tool or remote knowledge sourceThe agent or knowledge base calls the source's own API at question time, as the signed-in userNoSharePoint tool, Fabric data agent tool, Fabric IQ tool, Work IQ tool, remote SharePoint and Fabric knowledge sources
Indexed knowledge sourceAzure AI Search runs an indexer, chunks and embeds the content into a search indexYes, into the indexOneLake files, indexed SharePoint, blob

Remote sources keep permissions exact because the source enforces them on every call. Indexed sources give you control over ranking but need permission metadata carried into the index. Almost everything here is preview in October 2026.

This is also the bridge to Microsoft Fabric. If your Fabric estate is new, the sister site Fabric Field Notes covers the Fabric side of everything below.

What you will build

One support agent for Harbour Goods head office staff with two grounded tools:

  • A SharePoint tool over the support policies site, so policy answers come from the current Word documents and cite them.
  • A Fabric data agent tool over the sales lakehouse, so "how did ST-014 do in September?" is answered from Fabric, by the person asking, under their own permissions.

Then three routes to add when the need is real: Fabric IQ, OneLake files as a knowledge source and Work IQ.

Before you start

  • A Foundry project with a chat model such as gpt-5.4-mini.
  • Developers and end users with at least Foundry User on the project (formerly Azure AI User).
  • SharePoint and Foundry in the same Microsoft Entra tenant. The same goes for Fabric. Cross-tenant token exchange is not supported.
  • For SharePoint: each user needs a Microsoft 365 Copilot licence, or the pay-as-you-go model for the Copilot Retrieval API, plus read access to the site.
  • For Fabric: a paid F2 or higher capacity (or Power BI Premium P1 or higher with Fabric enabled), a published Fabric data agent and read access for every user to the agent and its data sources.
  • The three Harbour Goods policies saved as Word documents in a SharePoint library. The Retrieval API behind the SharePoint tool supports .doc, .docx, .pptx, .pdf, .aspx and .one for semantic and hybrid retrieval, not Markdown. The sources are the returns policy, delivery promise and warranty terms.

Step 1: add the SharePoint tool

  1. In the Foundry portal, open your agent and add the SharePoint tool. You can add only one per agent.
  2. Create a SharePoint connection with the site or folder URL, in one of these shapes:
    • https://<company>.sharepoint.com/sites/<site_name>
    • https://<company>.sharepoint.com/sites/<site_name>/Shared%20documents/<folder_name>
  3. Do not paste the full browser address. Learn warns that query strings and extra path parts are not supported.
  4. Save the connection and note its name.

In code, the tool takes the connection ID. This is the Learn prompt agent sample, trimmed:

from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import (
    PromptAgentDefinition,
    SharepointGroundingToolParameters,
    SharepointPreviewTool,
    ToolProjectConnection,
)
from azure.identity import DefaultAzureCredential

project = AIProjectClient(
    endpoint="https://<resource>.services.ai.azure.com/api/projects/<project>",
    credential=DefaultAzureCredential(),
)
sharepoint = project.connections.get("hg-support-policies")

sharepoint_tool = SharepointPreviewTool(
    sharepoint_grounding_preview=SharepointGroundingToolParameters(
        project_connections=[ToolProjectConnection(project_connection_id=sharepoint.id)]
    )
)

Run it as a person. The SharePoint tool uses delegated, on-behalf-of authentication. App-only and service principal identities fail with AppOnly OBO tokens not supported by target service. Locally, DefaultAzureCredential must resolve to your az login identity, not a managed identity.

Step 2: add the Fabric data agent tool

  1. In Fabric, open the published data agent. Copy workspace_id and artifact_id from its URL, which looks like .../groups/<workspace_id>/aiskills/<artifact_id>....
  2. In Foundry, add the Microsoft Fabric data agent tool to the same agent and enter both GUIDs. Foundry creates the project connection.
  3. Name the connection hg-sales-fabric.

Then build the agent with both tools and instructions that say which question goes where:

from azure.ai.projects.models import FabricDataAgentToolParameters, MicrosoftFabricPreviewTool

fabric = project.connections.get("hg-sales-fabric")
fabric_tool = MicrosoftFabricPreviewTool(
    fabric_dataagent_preview=FabricDataAgentToolParameters(
        project_connections=[ToolProjectConnection(project_connection_id=fabric.id)]
    )
)

agent = project.agents.create_version(
    agent_name="harbour-head-office",
    definition=PromptAgentDefinition(
        model="gpt-5.4-mini",
        instructions=(
            "For returns, delivery and warranty policy questions, use the SharePoint tool and cite the document. "
            "For sales, order and store performance numbers, use the Fabric tool. "
            "Never estimate a number. If neither tool answers, say you do not know."
        ),
        tools=[sharepoint_tool, fabric_tool],
    ),
)

The model you pick here only orchestrates and writes the reply. Learn is explicit that it does not change the model the Fabric data agent uses for NL2SQL. Fabric answer quality is decided in Fabric. Fabric Field Notes covers that in Data agents in production and AI-ready semantic models.

Step 3: Fabric IQ, when an ontology exists

Fabric IQ is the semantic layer in Fabric. The Foundry Fabric IQ tool (preview) lets an agent hand a question to an ontology, a Power BI semantic model or a Fabric data agent and get an answer in business terms. Learn recommends adding it through a toolbox, so one governed MCP endpoint serves many agents.

Add it once Harbour Goods models Store, Order and Product as an ontology. Until then the Fabric data agent tool is simpler. Whether the ontology is worth building is a Fabric question: see Fabric IQ and ontologies.

Step 4: OneLake files as a Foundry IQ knowledge source

Supplier contracts already land in the Files folder of a Fabric lakehouse. To make them a knowledge source:

  1. On the lakehouse workspace, add the Azure AI Search service's managed identity with the Contributor role. Learn's vector quickstart notes that Viewer is not enough to pull data into an index.
  2. In Foundry, select Build > Knowledge, select your Azure AI Search resource and select Create a knowledge base.
  3. Choose Microsoft OneLake and select Connect.
  4. Enter the workspace ID and lakehouse ID from the lakehouse URL, https://app.powerbi.com/groups/<WORKSPACE_ID>/lakehouses/<LAKEHOUSE_ID>.
  5. Select Create, then Save knowledge base.

This one does copy. It indexes the files, including files that arrive through shortcuts, into Azure AI Search. The search service must be Basic tier or higher and in the same tenant as the workspace. Private synchronisation is not supported for indexed OneLake sources yet.

Step 5: Work IQ, for questions about work itself

Work IQ gives an agent the signed-in user's Microsoft 365 context: email, meetings, files and chats. The Foundry tool type is work_iq_preview. Setup needs a Global Administrator once, to provision the Work IQ service principal and grant admin consent for WorkIQAgent.Ask. Creating the connection needs Foundry Project Manager. Learn's Foundry page bills the Work IQ API path through Copilot Credits, while the Microsoft 365 quickstart lists a Microsoft 365 Copilot licence per calling user. Confirm which applies to your tenant before you promise it to anyone.

A minimal toolbox definition from Learn, created with azd ai toolbox create my-toolbox --from-file my-toolbox.yaml:

description: Work IQ toolbox
tools:
  - type: work_iq_preview
    project_connection_id: my-workiq-conn

For Harbour Goods the use is narrow: "summarise this week's emails from the Pune West store manager about stock". Only Work IQ has that.

Check it worked

Test with two real accounts, one with access to the policies site and the sales workspace, one without.

TestExpected with accessExpected without access
"How long is the returns window?"30 days from delivery, with a URL citation to the returns policy document in SharePointNo policy content, no citation
"What were ST-014 net sales last month?"A number from the Fabric data agent, matching what the data agent returns in FabricAn unauthorized error from the Fabric tool
"What is the Jaipur delivery promise?"5 working days, cited from the delivery promiseNo policy content

The second column is the proof. Learn's SharePoint article asks for exactly this: confirm retrieval for one user, then confirm a second user without access gets nothing from the restricted document. A grounded agent that answers both users the same way is not using their identity.

Where this breaks

  • Teams. Learn says the SharePoint tool does not work when the agent is published to Microsoft Teams.
  • Throughput. The Copilot Retrieval API behind the SharePoint tool returns at most 25 results, allows 200 requests per user per hour and caps the query at 1,500 characters.
  • Region and capacity. The Fabric data agent cannot query a data source whose workspace capacity is in a different region from the data agent.
  • Unpublished data agents. Cannot find the requested item usually means the Fabric data agent is not published or its configuration changed.
  • Service principals. The Fabric tool page lists service principal as an option in one place and says it is not supported in another. Plan on user identity until Learn settles it.
  • Data boundaries. Fabric data agent responses, OneLake content, Fabric IQ calls and Work IQ calls can be processed outside the Fabric or Azure compliance boundary, under Foundry's terms. Each Learn page says so. Put that in front of the data protection officer before the pilot, not after.

On the brewhouse floor

A winery's export manager asks: "Can we ship the 2024 reserve to the new distributor? How many cases are left?" The shipping rules live in a SharePoint document the compliance lead keeps current. The case count lives in a Fabric lakehouse refreshed nightly. One agent with both tools cites the rule and quotes the stock as the export manager is allowed to see it. Nobody exports the stock table to a spreadsheet that is wrong by Friday.
