Why evaluation comes before launch

An agent that sounds right is not the same as an agent that is right. Name the ways a Foundry agent fails, match each failure to the measurement that catches it, then take a ten-minute tour of where those measurements live in the Foundry portal.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 0 Ankur Napa EvaluationObservabilitySafety

Short answer

A language model writes fluent text whether or not it is true. That is the whole problem. The Harbour Goods support agent can tell a customer they have 45 days to return a kettle, in perfect English, with a friendly sign-off. The policy says 30. Nobody notices until the store manager does.

Evaluation is how you find that out before a customer does. Microsoft Foundry splits the work into three capabilities that Learn calls evaluation, monitoring and tracing. Evaluators score responses for quality, safety and agent behaviour. Tracing records what the agent did on each request. Monitoring watches the live agent with dashboards, scheduled checks and alerts in Application Insights.

The habit to build is simple. Write down what can go wrong, pick the measurement that catches each failure, then run those measurements on a test set before launch and on live traffic after it.

Two kinds of evaluator sit behind that table. AI-assisted evaluators use a model you deploy as a judge and return a score with a reason. Risk and safety evaluators run on Microsoft-hosted safety models and return a severity from 0 to 7, where the default threshold is 3. You can also write your own: code-based, prompt-based or endpoint-based custom evaluators, all in preview.

A ten-minute tour

You need a Foundry project with one agent in it, such as the one from Your first prompt agent. You do not build anything here. You look at where each measurement lives.

  1. Sign in to the Foundry portal. Make sure the New Foundry toggle is on, because these steps describe the new portal.
  2. Open your project. In the left pane, select Evaluation. This page lists every evaluation run with its status, target, evaluation tokens, target tokens and scores. On a new project it is empty.
  3. Open the evaluator catalogue. Learn shows two paths, Evaluation > Evaluator catalog and Build > Evaluations > Evaluator catalog, so the label may read either way in your tenant. Scroll the groups: general purpose, textual similarity, RAG, risk and safety, agent and rubric. Notice how many are marked preview.
  4. Go back to Evaluation and select Create. Read the first screen without submitting. The wizard asks for a target: Agent, Model, Dataset or Traces. Close the wizard.
  5. Open your agent and select the Playground tab. Select Metrics in the upper right. Playground evaluations are on by default for every project and are billed on consumption. If you do not want them, unselect every evaluator here.
  6. In the left navigation, select Agents, then select Traces at the top. If you see a Connect button, the project has no Application Insights resource yet. Tracing starts once one is connected. You will do that in Trace an agent run.
  7. Open your agent again and select the Monitor tab. This is the dashboard for token usage, latency, run success rate, evaluation scores and red teaming results. It is in preview and shows data only after tracing is connected.

That is the whole map. Evaluation runs live on the Evaluation page, single requests live on Traces and the running agent lives on Monitor.

What people get wrong

Treating a judge score as a fact. AI-assisted evaluators are a model grading a model. They are consistent at scale, not infallible. Read the reasons on failing rows, not just the average.

Testing only happy paths. A test set of twenty polite questions about delivery tells you nothing about the customer who pastes in a fake order ID or the store code ST-099 that does not exist. Put the awkward cases in on purpose.

Skipping ground truth. Relevance tells you the answer was on topic. It cannot tell you the answer was correct. For facts like the 30-day returns window or the 12-month electronics warranty, write the expected answer down and score against it.

Forgetting region and cost. Risk and safety evaluators run only in listed regions. In October 2026 that list has no Indian region, so a project in Central India can run batch evaluations but not safety evaluators. Every AI-assisted evaluator also spends tokens on the judge model. Twenty rows with five judged evaluators is a hundred judge calls per run.

Evaluating once. A score from launch week says nothing about week twelve. Models are updated, prompts get edited and customers find new ways to ask. Continuous evaluation exists because quality drifts.

On the brewhouse floor

Brewery A wants an assistant that answers cellar questions from its own SOPs: how long a lager sits in FV-03, what temperature to crash at, when to dump yeast. The failure that matters is the confident wrong number, such as two days of conditioning where the SOP says fourteen. Write twenty questions with the SOP answer next to each, run groundedness and response completeness against them and read every failing row before anyone on the cellar floor trusts it. The model sees the question. The head brewer knows which wrong answer costs a tank.
