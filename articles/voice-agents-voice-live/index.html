Voice agents with Voice Live: build a spoken agent, find the latency

Build a Harbour Goods voice agent as a voice-based prompt agent (preview), test it in the playground, script a spoken turn from Python and time how long the caller waits for the first sound. Then see which stage of the pipeline the wait comes from and what moves it.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa VoiceAgentsModels

Short answer

A voice agent in Foundry is a prompt agent whose interaction mode is Voice. You choose the instructions, a model, a voice and turn detection. Foundry runs the audio pipeline on Voice Live, so you host no speech stack. Two architectures sit underneath. A native speech-to-speech model such as gpt-realtime hears and speaks directly and is built for low latency. A cascaded setup runs speech recognition, a text model and speech synthesis in sequence, which gives more model and voice choice and adds a delay at every stage.

Measure two numbers, not one: time to first token from the model and time to first audio at the caller. Turn detection, content filtering, region and prompt length all sit between them. Voice-based agents are in preview. The GA overview lists Agents with Voice Live as preview too.

What you will build

Harbour Goods wants callers to ask about delivery and returns by phone without waiting for a person between 9 AM and 9 PM IST. You will:

  • Create a voice agent hg-voice in the portal and test it with your microphone.
  • Create the same agent from Python and send it one turn, saving the reply as a WAV file.
  • Add two timers to the script and read where the time goes.

Before you start

  • A Foundry project and the Foundry User role on it.
  • Access to the voice agent preview in your subscription and region. If Voice is missing as an interaction mode, this is why.
  • A voice model available to the project, such as gpt-realtime. Check the project's Models page.
  • For the script: Python 3.10 or later and az login.

Step 1: create the agent in the portal

  1. Sign in to Microsoft Foundry and open your project.
  2. Go to Agents and select Build an agent.
  3. In Agent name, enter hg-voice.
  4. Under Interaction mode, select Voice. You cannot change this later; a text agent cannot become a voice agent.
  5. Pick the closest use case, then select Create agent and open playground.

Step 2: write instructions for the ear

Text instructions do not carry over well. A caller cannot scroll back. Replace the defaults with:

You are the Harbour Goods phone assistant.
- Speak in short sentences and ask one question at a time.
- Policies: returns within 30 days with a receipt or order ID; standard
  delivery 3 working days in metro cities and 5 elsewhere; electronics
  warranty 12 months; support 9 AM to 9 PM IST.
- Read order IDs back in groups, for example "H G, 2 4 0 3 1 8, 0 0 4 2".
- Never read a full payment card or phone number aloud.
- If the caller wants a refund processed or is upset, offer a person.
- If a tool fails, say so and do not claim the change succeeded.

Select Save, then Start session. Allow microphone access. Ask about returns, interrupt the agent halfway through an answer and pause in the middle of a sentence. Learn's checks: the transcript matches your words, the reply is short enough to follow by ear, the agent waits through natural pauses and an interruption stops it. Select End before you change any settings; configuration is locked during a session.

Step 3: create the agent from Python

Install the voice extra. Learn's examples target azure-ai-projects 2.8.0 or later; the install line asks for at least 2.7.0.

python -m pip install "azure-ai-projects[voice]>=2.8.0" azure-identity
export FOUNDRY_PROJECT_ENDPOINT="https://<account>.services.ai.azure.com/api/projects/<project>"
export FOUNDRY_VOICE_AGENT_NAME="hg-voice-code"
import os

from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import (
    VoiceAgentAudioConfig,
    VoiceAgentAudioOutputConfig,
    VoiceAgentDefinition,
    VoiceModelType,
    VoiceOutputModality,
    VoiceType,
)
from azure.identity import DefaultAzureCredential

definition = VoiceAgentDefinition(
    model_type=VoiceModelType.MANAGED,
    model="gpt-realtime",
    instructions=(
        "You are the Harbour Goods phone assistant. Speak in short sentences. "
        "Returns: 30 days with receipt or order ID. Delivery: 3 working days "
        "in metro cities, 5 elsewhere. Support: 9 AM to 9 PM IST."
    ),
    audio=VoiceAgentAudioConfig(
        output=VoiceAgentAudioOutputConfig(
            voice="en-US-AvaNeural",
            voice_type=VoiceType.AZURE_STANDARD,
        ),
    ),
    output_modalities=[VoiceOutputModality.AUDIO],
    store=True,
)

with (
    DefaultAzureCredential() as credential,
    AIProjectClient(
        endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
        credential=credential,
        allow_preview=True,
    ) as project_client,
):
    created = project_client.agents.create_version(
        agent_name=os.environ["FOUNDRY_VOICE_AGENT_NAME"], definition=definition
    )
    print(f"Created voice agent, version {created.version}")

allow_preview=True is required to create voice definitions through .agents. store=True keeps the transcript and audio so you can read the call back later. The endpoint is live as soon as the first version exists; there is no separate deploy step.

Step 4: send a turn and time it

This follows Learn's talk sample: it types the turn, so it runs without a microphone. It saves the reply as 24 kHz mono PCM16 in a WAV file. Two timers are added: when the request went out, when the first audio arrived and when the response finished.

import os
import time
import wave

from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import (
    RealtimeConversationItemMessageUser,
    RealtimeConversationItemMessageUserContent,
    RealtimeConversationItemType,
    RealtimeServerEventError,
    RealtimeServerEventResponseAudioDelta,
    RealtimeServerEventResponseDone,
    VoiceAgentDefinition,
)
from azure.identity import DefaultAzureCredential

agent_name = os.environ["FOUNDRY_VOICE_AGENT_NAME"]

with (
    DefaultAzureCredential() as credential,
    AIProjectClient(
        endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
        credential=credential,
        allow_preview=True,
    ) as project_client,
):
    definition = project_client.agents.get(agent_name=agent_name).versions.latest.definition
    if not isinstance(definition, VoiceAgentDefinition):
        raise TypeError("The agent must have a voice definition.")

    with project_client.beta.voice_agents.realtime.connect(agent_name=agent_name) as conn:

        def drain():
            chunks, first_audio = [], None
            while True:
                event = conn.recv(timeout=45)
                if isinstance(event, RealtimeServerEventResponseAudioDelta):
                    first_audio = first_audio or time.perf_counter()
                    chunks.append(event.delta)
                elif isinstance(event, RealtimeServerEventError):
                    raise RuntimeError(event.error.message)
                elif isinstance(event, RealtimeServerEventResponseDone):
                    return chunks, first_audio, time.perf_counter()

        if definition.greeting is not None:
            # Skip the greeting, which is its own response
            drain()

        conn.conversation.item.create(
            item=RealtimeConversationItemMessageUser(
                type=RealtimeConversationItemType.MESSAGE,
                content=[RealtimeConversationItemMessageUserContent(
                    type="input_text",
                    text="How long does delivery to Chennai take?",
                )],
            )
        )
        sent = time.perf_counter()
        conn.response.create()
        chunks, first_audio, done = drain()

if not chunks:
    raise RuntimeError("No audio returned.")
print(f"Time to first audio: {(first_audio - sent) * 1000:.0f} ms")
print(f"Time to response done: {(done - sent) * 1000:.0f} ms")
with wave.open("reply.wav", "wb") as wav:
    wav.setnchannels(1)
    wav.setsampwidth(2)
    wav.setframerate(24000)
    wav.writeframes(b"".join(chunks))

Run it five times and keep every number. One run tells you nothing about a phone line.

Where the latency goes

A typed turn skips the microphone and turn detection, so the script measures the server side. A real caller waits for all of it.

StageApplies toWhat adds timeWhat moves it
Turn detectionBothWaiting for silence before deciding the caller finished. Voice Live's semantic VAD defaults to 500 ms of silenceTune silence duration and end-of-utterance detection; too short and the agent interrupts people.
Speech recognitionCascadedTranscribing the caller before the text model can startUse a speech-to-speech model, or keep phrase lists short.
ModelBothTime to first token, longer with long instructions, retrieved context and many toolsShort prompts, short spoken answers, a model whose reasoning time fits.
Content filteringBoth, worst for cascadedSynchronous output filtering buffers text before speech can startAsynchronous filtering where the model supports it and your safety policy allows.
Network and regionBothDistance between the voice agent resource and the modelA regional or Data Zone deployment near the resource; measure against Global rather than assume.
Synthesis and playbackBothGenerating audio and buffering it on the clientPlay each audio delta as it arrives instead of buffering the whole reply.

The trade-off on filtering is real. With asynchronous filtering, content can be spoken before a late policy signal arrives. Spoken words cannot be taken back. If your policy needs moderation before anything is heard, keep synchronous checks and budget for the delay.

Where this breaks

  • Preview. Voice-based agents, their monitoring, telephony and avatars are preview features. Labels, models and defaults move. Treat the portal values as authoritative over this page.
  • Region and access. No Voice option or an empty model list means preview access, region or model availability.
  • Mode is fixed. A voice agent is created as one. Plan a separate agent rather than converting hg-support.
  • Typed turns flatter the numbers. Measure a real microphone path before quoting latency to anyone.
  • Phone lines are a separate build. Built-in telephony covers Teams Phone extensibility and Twilio. The provider connection and number binding come after this.

On the brewhouse floor

On a packaging line nobody has a free hand for a keyboard. Brewery A's line operator wants to ask "what is the fill target on line 2 for the 330 ml cans?" with gloves on and a seamer running. A voice agent fits, but the noise floor near a canning line is nothing like a quiet office. Test turn detection on the floor itself, with the line running, before you quote anyone a response time.
