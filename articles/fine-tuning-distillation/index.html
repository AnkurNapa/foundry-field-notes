Fine-tuning and distillation: prove it beats a better prompt

Fine-tune only after a good prompt has stalled. Measure the prompt first, train a small model on teacher-labelled examples, then compare both on the same held-out test set.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 3 Ankur Napa ModelsEvaluationCost

Short answer

Fine-tuning changes a model's weights with your examples. It can make a small model as accurate as a big one on a narrow task. It also removes the examples you were stuffing into every prompt. In exchange, it adds training cost, hosting cost and a second retirement clock.

So earn it. First write the best prompt you can and score it on a held-out test set. Then fine-tune, score the fine-tuned model on the same set and keep it only if it wins on accuracy, tokens or both. Distillation is the cheap way to get training data: a large teacher model labels your real messages. A small student model learns from those labels.

This step covers the AI-103 skill areas Implement text analysis solutions (customising model outputs for domain tasks) and Implement generative AI and agentic solutions (evaluating models and apps).

The symptom

Harbour Goods routes every support message to one of six queues: returns, delivery, warranty, billing, store and escalate. The router runs on gpt-5.4-mini with a few-shot prompt: the instructions plus twelve worked examples, two per queue. Accuracy is acceptable. The bill isn't. Every message, however short, carries the same block of examples.

PromptApproximate tokens
Few-shot prompt (instructions plus 12 examples)234
Instructions only35
Average customer message in the test set10

Those counts use the Learn rule of thumb of four characters per token. The real numbers come back in usage.input_tokens.

Measure it

Three files in public/samples, all synthetic:

FileRowsUse
fine-tuning-distillation-train.jsonl60Training examples in chat format.
fine-tuning-distillation-validation.jsonl20Validation during training.
fine-tuning-distillation-test.csv30Held-out test set. Never train on it.
fine-tuning-distillation-prompt-instructions.txt1The short prompt.
fine-tuning-distillation-prompt-few-shot.txt1The short prompt plus 12 examples.

The test set has 9 returns, 5 escalate, 4 delivery, 4 warranty, 4 billing and 4 store messages. Always guessing "returns" scores 30.0 percent. Any model has to clear that floor by a wide margin.

Score each candidate with one script. Save it as score.py:

import csv
import sys

from azure.identity import DefaultAzureCredential
from azure.ai.projects import AIProjectClient

PROJECT_ENDPOINT = "https://hg-foundry-dev.services.ai.azure.com/api/projects/support-agent"
QUEUES = {"returns", "delivery", "warranty", "billing", "store", "escalate"}

deployment, prompt_file = sys.argv[1], sys.argv[2]
instructions = open(prompt_file).read()

project = AIProjectClient(endpoint=PROJECT_ENDPOINT, credential=DefaultAzureCredential())
openai = project.get_openai_client()

rows = list(csv.DictReader(open("fine-tuning-distillation-test.csv")))
correct = invalid = input_tokens = 0
for row in rows:
    response = openai.responses.create(
        model=deployment, instructions=instructions, input=row["message"], max_output_tokens=16
    )
    answer = response.output_text.strip().lower()
    invalid += answer not in QUEUES
    correct += answer == row["queue"]
    input_tokens += response.usage.input_tokens

print(f"{deployment}: {correct}/{len(rows)} correct, {invalid} invalid labels, "
      f"{input_tokens / len(rows):.0f} input tokens per call")

max_output_tokens caps everything the model generates, including reasoning tokens. If a reasoning model returns an empty answer, raise the cap.

Run the two prompt baselines:

python score.py gpt-5.4-mini fine-tuning-distillation-prompt-instructions.txt
python score.py gpt-5.4-mini fine-tuning-distillation-prompt-few-shot.txt

Write both results down before you train anything. That is the bar.

Fix it

Decide whether to fine-tune at all

SignalDo this instead of fine-tuning
The model lacks current factsRetrieval. Fine-tuning doesn't replace it.
Few-shot accuracy is already at targetKeep the prompt. Try a cheaper model with it first.
Errors cluster on one confusing pair of queuesFix the instructions for that pair, then rescore.
Accuracy is fine but the example block dominates tokens on high volumeFine-tune a small model. This is the case here.
A small model must match a big one on one narrow taskDistil. Also the case here.

Distil: let a teacher label the data

Run a large model with the few-shot prompt over a pool of real, unlabelled messages. Keep only answers that are valid queue names. Spot-check a sample by hand. Then write each pair in the chat format training expects, one conversation per line:

{"messages": [{"role": "system", "content": "Route the Harbour Goods support message to one queue: returns, delivery, warranty, billing, store, escalate. Reply with the queue name only."}, {"role": "user", "content": "I was charged twice for the iron"}, {"role": "assistant", "content": "billing"}]}

Notice the system message in the training data is the short one. The student learns the behaviour, so it doesn't need the examples at run time. That is where the token saving comes from.

The sample training file already has this shape. In a real project, the teacher would be a larger current model such as gpt-5.4. You would also keep the teacher's raw outputs for audit.

Pick a base model you can actually train

In October 2026, supervised fine-tuning (SFT) in the current Foundry experience supports, among others, gpt-4.1, gpt-4.1-mini, gpt-4.1-nano, gpt-4o, gpt-4o-mini, gpt-oss-20b, Llama-3.3-70B-Instruct, Qwen3-32B and Ministral-3B. Check the supported models table before you start, because method, training type and deployment option vary by model.

Read the retirement schedule at the same time. Every OpenAI model with SFT in that table is already marked Deprecated. gpt-4.1-nano version 2025-04-14 retires on 14 April 2027. Fine-tuned gpt-4.1-nano deployments retire on 14 October 2027. That is enough for a measured experiment, not for a five-year plan. gpt-oss-20b supports SFT with Global Standard serving and has no retirement date listed.

This walkthrough trains gpt-4.1-nano with Global training.

Train

import os
from azure.ai.projects import AIProjectClient
from azure.identity import DefaultAzureCredential

project = AIProjectClient(
    endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)
client = project.get_openai_client()

with open("fine-tuning-distillation-train.jsonl", "rb") as training:
    training_file = client.files.create(file=training, purpose="fine-tune")
with open("fine-tuning-distillation-validation.jsonl", "rb") as validation:
    validation_file = client.files.create(file=validation, purpose="fine-tune")
client.files.wait_for_processing(training_file.id)
client.files.wait_for_processing(validation_file.id)

job = client.fine_tuning.jobs.create(
    model="gpt-4.1-nano-2025-04-14",
    training_file=training_file.id,
    validation_file=validation_file.id,
    suffix="hg-router",
    method={
        "type": "supervised",
        "supervised": {
            "hyperparameters": {
                "batch_size": "auto",
                "learning_rate_multiplier": "auto",
                "n_epochs": "auto",
            }
        },
    },
    extra_body={"trainingType": "GlobalStandard"},
)
print(job.id, job.status)

Confirm the exact model identifier against the supported models table. The training role is Foundry User. Deploying the result needs Foundry Owner.

Watch train_loss, full_valid_loss and full_valid_mean_token_accuracy in the job's Monitor view, or list events and checkpoints with client.fine_tuning.jobs.list_events(job.id) and client.fine_tuning.jobs.checkpoints.list(job.id). If training loss falls while validation loss rises, the model is memorising. Don't assume the last checkpoint is the best one.

Deploy for evaluation

Deploy the fine-tuned model from the portal. For the test, choose the Developer deployment type where your model supports it. It has no hourly hosting fee, lasts 24 hours and carries no SLA. That is exactly right for scoring 30 rows.

Prove it

Run the same script on the fine-tuned deployment with the short prompt:

python score.py gpt-4.1-nano-ft-hg-router fine-tuning-distillation-prompt-instructions.txt

Fill the table from your three runs. The token column is computed from the sample files. The accuracy column comes only from your runs.

CandidatePromptApproximate input tokens per callCorrect out of 30
FloorAlways "returns"Not applicable9 (30.0 percent).
gpt-5.4-miniInstructions only45Your run.
gpt-5.4-miniFew-shot244Your run.
Fine-tuned gpt-4.1-nanoInstructions only45Your run.

The saving is about 199 input tokens per call. At 10,000 messages that is about 1,990,000 input tokens you no longer send.

Ship the fine-tune only if all three hold:

  1. It scores at least as well as the few-shot prompt on the 30 held-out rows.
  2. It returns no invalid labels.
  3. The token saving, priced at your region's rates, beats the fine-tuned model's hosting charge for your volume. Fine-tuned deployments on Standard bill hosting hours even when idle. Global Standard serving has per-token billing.

If the fine-tune loses, you have still learned something cheap: the prompt was good enough.

Where this breaks

  • Leaking the test set. If test rows end up in training, the score means nothing. Keep the three files apart from day one.
  • Too little data. Sixty rows is enough to see a trend, not to ship. Learn's classic guidance suggests 50 to 100 examples to test and 500 or more for production.
  • Teacher mistakes become student habits. Distillation copies the teacher's errors. Hand-check a sample of teacher labels before training.
  • Limits. In October 2026, 100 training jobs per resource, three running at once for standard and global training, 10 fine-tuned deployments and 1 GB of fine-tuning files per resource.
  • Region and type. Global training doesn't offer data residency. Data zone training supports only the US zone.
  • Two retirement clocks. A fine-tuned model can't auto-upgrade. When its base retires, you retrain on a new base and rerun this whole comparison.
  • Stored completions. The older stored-completions distillation flow is deprecated. Build the teacher dataset yourself, as above.

On the brewhouse floor

A distillery's quality team sorts customer complaints into six types: off-aroma, haze, closure, label, delivery and other. Distillery A first tried a long prompt full of examples, then distilled a large model's labels into a small one. Both scored the same on 50 held-out complaints. The small model needed a fifth of the input tokens, so it stayed. The day its base model's retirement date arrived on the calendar, the team reran the same 50.
