Foundry IQ knowledge bases: agentic retrieval with citations

Turn the Harbour Goods policy container into a Foundry IQ knowledge base, connect it to a prompt agent through its MCP endpoint and watch agentic retrieval split a two-part complaint into subqueries. Every answer cites its source. The agent says I don't know when the policies are silent.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 2 Ankur Napa KnowledgeSearchAgentsMCP

Short answer

A Foundry IQ knowledge base is a reusable retrieval layer that many agents can share. It holds one or more knowledge sources and a set of rules for how to search them. When an agent asks a question, the knowledge base uses agentic retrieval: an LLM can plan the query, split it into subqueries, run them in parallel as keyword, vector or hybrid searches, rerank the results semantically and return merged content with references. Azure AI Search does the indexing and retrieval underneath.

The agent reaches the knowledge base through a Model Context Protocol (MCP) endpoint that exposes one tool, knowledge_base_retrieve. Learn says this is the only tool currently supported with Foundry Agent Service.

Watch the preview line. Some Foundry IQ features are generally available and others are not. On the 2026-04-01 REST API you get generally available knowledge sources with minimal, extractive retrieval. LLM query planning, answer synthesis, non-minimal reasoning effort and multi-turn messages need 2026-08-01-preview. Learn also says the Foundry and Azure portals give preview-only access to all agentic retrieval features. For AI-103, this step covers Choose an appropriate method for retrieval and indexing and Connect retrieval pipelines directly to workflows and agent tools.

What you will build

A knowledge base called hg-policy-kb with one blob knowledge source over the three Harbour Goods policies. A prompt agent called harbour-support-kb that calls it through a project connection, cites every fact and refuses when the policies do not cover the question.

Upload the three policy files to a blob container called policies first:

  • Returns policy
  • Delivery promise
  • Warranty terms

Before you start

  • A Foundry project, not a hub-based project. Learn states hub projects are not supported here.
  • A chat model deployment such as gpt-5.4-mini and an embedding deployment such as text-embedding-3-small.
  • An Azure AI Search service in a region that supports agentic retrieval, with role-based access enabled (on Settings > Keys, set API Access control to Both or Role-based access control) and a system-assigned managed identity.
  • Roles, from the Foundry IQ connection article:

Step 1: create the knowledge base in the portal

  1. Sign in to Microsoft Foundry with the New Foundry toggle on and open your project.
  2. Select Build, then the Knowledge tab.
  3. Connect your Azure AI Search service, or select it if it is already listed.
  4. Select Create a knowledge base.
  5. Choose Azure Blob Storage as the knowledge type and select Connect. Point it at the storage account and the policies container and pick the embedding deployment. The knowledge source generates its own data source, skillset, index and indexer, so you do not run the Import data wizard.
  6. Name the knowledge base hg-policy-kb. Pick gpt-5.4-mini as the model.
  7. Set the retrieval reasoning effort to low. Learn describes three levels: minimal skips the LLM and sends queries straight to the sources, low is the default and plans subqueries, medium adds an iterative pass.
  8. Leave the output mode on answer synthesis, which is the portal default, or switch to extractive data if you want raw passages for your own model.
  9. Save the knowledge base.

Field labels in the knowledge source pane change between rollouts. The order of decisions does not: source, embedding model, chat model, reasoning effort, output mode.

Step 2: try it from the Agents tab

Learn's portal workflow is short. On the Agents tab, create or select an agent, connect it to the knowledge base and use the playground. Do that once with any agent to see the knowledge base answer. The playground is for proof of concept. When you move to code, Learn says to configure managed identities and permissions properly, which is the next step.

Step 3: connect an agent in code

Install the packages with pip install "azure-ai-projects>=2.0.0" requests azure-identity. Then create a RemoteTool project connection that points at the knowledge base's MCP endpoint and authenticates with the project's managed identity. This is the Learn sample with Harbour Goods names.

import requests
from azure.identity import DefaultAzureCredential, get_bearer_token_provider

credential = DefaultAzureCredential()
project_resource_id = "/subscriptions/<sub>/resourceGroups/<rg>/providers/Microsoft.CognitiveServices/accounts/<account>/projects/<project>"
connection_name = "hg-policy-kb-mcp"
search_endpoint = "https://<your-search>.search.windows.net"
mcp_endpoint = f"{search_endpoint}/knowledgebases/hg-policy-kb/mcp?api-version=2026-08-01-preview"

token = get_bearer_token_provider(credential, "https://management.azure.com/.default")
response = requests.put(
    f"https://management.azure.com{project_resource_id}/connections/{connection_name}?api-version=2025-10-01-preview",
    headers={"Authorization": f"Bearer {token()}"},
    json={
        "name": connection_name,
        "type": "Microsoft.MachineLearningServices/workspaces/connections",
        "properties": {
            "authType": "ProjectManagedIdentity",
            "category": "RemoteTool",
            "target": mcp_endpoint,
            "isSharedToAll": True,
            "audience": "https://search.azure.com/",
            "metadata": {"ApiType": "Azure"},
        },
    },
)
response.raise_for_status()

Now create the agent with the MCP tool. The instructions follow Learn's template: always use the tool, cite sources, say I don't know when retrieval comes back empty.

from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import MCPTool, PromptAgentDefinition

project = AIProjectClient(
    endpoint="https://<resource>.services.ai.azure.com/api/projects/<project>",
    credential=credential,
)

kb_tool = MCPTool(
    server_label="knowledge-base",
    server_url=mcp_endpoint,
    require_approval="never",
    allowed_tools=["knowledge_base_retrieve"],
    project_connection_id=connection_name,
)

agent = project.agents.create_version(
    agent_name="harbour-support-kb",
    definition=PromptAgentDefinition(
        model="gpt-5.4-mini",
        instructions=(
            "You are the Harbour Goods support agent. Use the knowledge base tool to answer every question. "
            "Never answer from your own knowledge. Cite the policy and section for each fact. "
            "If the knowledge base does not contain the answer, respond with \"I don't know\"."
        ),
        tools=[kb_tool],
    ),
)

openai_client = project.get_openai_client()
conversation = openai_client.conversations.create()
answer = openai_client.responses.create(
    conversation=conversation.id,
    input="My order to Jaipur arrived two days after the promised date and the kettle inside was faulty. What am I entitled to?",
    extra_body={"agent_reference": {"name": agent.name, "type": "agent_reference"}},
)
print(answer.output_text)

Check it worked

The Jaipur question is deliberately two questions in one. A good run plans at least two subqueries, one about late delivery and one about faulty products. It then cites both policies.

QuestionExpected answerSources
Jaipur order late, kettle faultyINR 150 voucher for the late delivery, valid 90 days. Faulty on arrival, so returnable within 30 days with the delivery charge refundedD4, R3, R6
What is the warranty on a sofa?6 months against manufacturing defectsW1
Can I return opened made-to-measure blinds?No, made-to-measure curtains and blinds cannot be returnedR4
Do you offer gift wrapping?I don't knowNone

Learn adds one detail worth checking: citation URLs vary by knowledge source. Blob knowledge sources return the original document URL. Search index knowledge sources fall back to the knowledge base's MCP endpoint. If your citations point to the MCP endpoint, you built a search index source, not a blob source.

Where this breaks

  • The agent skips the tool. Learn's troubleshooting says to confirm allowed_tools includes knowledge_base_retrieve and to make the instructions require the knowledge base and an I don't know fallback.
  • 403 from Azure AI Search. The project's managed identity is missing Search Index Data Reader. A 403 from Resource Manager when creating the connection is your own permissions.
  • 400 or 404 from the MCP endpoint. Wrong search endpoint, wrong knowledge base name or the wrong API version. Use 2026-08-01-preview.
  • Permissions are not automatic. For sources with access control lists, you must index the permission metadata and pass the user's token in the x-ms-query-source-authorization header. Without the token, Learn says permission-enabled sources return results unfiltered.
  • Cost moves with effort. Agentic retrieval bills Azure AI Search retrieval tokens and Azure OpenAI tokens for planning and synthesis. Fewer knowledge sources and lower reasoning effort cost less. Read the response's activity log to see what ran.
  • Deleting the agent leaves the knowledge base. Delete the knowledge base and knowledge source on the search service separately.

On the brewhouse floor

A restaurant group runs a knowledge base over its allergen sheets, recipe cards and supplier specifications. A server asks: "Is the house dressing safe for a nut allergy? Does the bread come from the same supplier as last month?" That is two questions across two document sets. Agentic retrieval splits them, cites the allergen sheet for one and the supplier spec for the other and says I don't know if the dressing recipe was never uploaded. For allergens, I don't know is the correct answer. A confident guess is not.
