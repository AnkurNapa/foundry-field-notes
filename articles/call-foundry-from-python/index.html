Call Foundry from Python: run an agent from your own code

Use the Foundry SDK (azure-ai-projects 2.x) with keyless auth to call a model, create a versioned prompt agent and hold a two-turn conversation with it from a Python script. Built around the Harbour Goods support agent, with the output to expect at each step.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 1 Ankur Napa SDKAgentsSecurity

Short answer

Install azure-ai-projects 2.x and azure-identity. Create an AIProjectClient with your project endpoint and DefaultAzureCredential. From there, project.get_openai_client() gives you an OpenAI-compatible client for the Responses API. project.agents.create_version() saves a prompt agent as a named, versioned asset. project.get_openai_client(agent_name=...) gives you a client bound to that agent. conversations.create() keeps the history between turns. No API keys anywhere. Your identity needs the Foundry User role on the project.

The trap: Learn's Python samples for the new Foundry use azure-ai-projects>=2.3.0. Code written for 1.x (threads, runs, connection strings) does not run against it.

What you will build

Harbour Goods wants its support agent defined in code, not only in the portal, so that every change is reviewed and versioned. By the end you will have one script, hg_support.py, that:

  • Sends a plain prompt to a deployed model, to prove the endpoint and identity work.
  • Creates (or adds a version to) a prompt agent called hg-support with Harbour Goods instructions.
  • Asks it a returns question, then a follow-up that only makes sense if it remembers the first.

Before you start

  • A Foundry project with a chat model deployment. The Learn quickstart deploys gpt-5-mini under the deployment name gpt-5-mini. If you use another current model, such as gpt-5.4-mini, change the name in the code to match your deployment name.
  • The Foundry User role on the project. Learn notes this role was previously called Azure AI User. Owner or Contributor alone does not let you create agents.
  • Python 3.10 or later and the Azure CLI.
  • The developer tools from The developer toolchain, or at least the SDK in a virtual environment.

Step 1: install and sign in

python3 -m venv .venv
source .venv/bin/activate
pip install "azure-ai-projects>=2.3.0" azure-identity
az login

DefaultAzureCredential tries several credential sources in turn. On a laptop it uses your Azure CLI sign-in. In Azure it uses the app's managed identity. The same code works in both places.

Step 2: find your project endpoint

  1. Sign in to Microsoft Foundry with the New Foundry toggle on.
  2. Open your project and copy the endpoint from the Overview page.
  3. Save it as an environment variable so it stays out of the code:
export FOUNDRY_PROJECT_ENDPOINT="https://<resource-name>.services.ai.azure.com/api/projects/<project-name>"
export FOUNDRY_MODEL="gpt-5-mini"

If your organisation uses a custom subdomain, the endpoint uses that subdomain in place of the resource name.

Step 3: call the model

Start with the smallest call. If this fails, the agent code will fail for the same reason, with a longer stack trace.

import os

from azure.ai.projects import AIProjectClient
from azure.identity import DefaultAzureCredential

project = AIProjectClient(
    endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)
openai = project.get_openai_client()

response = openai.responses.create(
    model=os.environ["FOUNDRY_MODEL"],
    input="Reply with the single word: ready",
)
if not response.output_text or not response.output_text.strip():
    raise RuntimeError("Response output text was empty.")
print(f"Model says: {response.output_text}")

The model value is your deployment name, not the catalogue name. They are often the same, which is why the mismatch surprises people when they are not.

Step 4: create the agent as a versioned asset

An agent bundles a model, instructions and optional tools under one name. Each create_version call adds a version. Agents are identified by name and version; there is no separate agent GUID any more.

from azure.ai.projects.models import PromptAgentDefinition

AGENT_NAME = "hg-support"

INSTRUCTIONS = """You are the Harbour Goods customer support agent.
Harbour Goods is a retailer with six stores in India. Prices are in INR.
Policies you can state:
- Returns are accepted within 30 days with a receipt or order ID.
- Standard delivery is 3 working days in metro cities and 5 elsewhere.
- Electronics carry a 12 month warranty.
- Support hours are 9 AM to 9 PM IST.
Order IDs look like HG-240318-0042. If you do not know an answer, say so
and offer to pass the question to a person. Keep answers under 60 words."""

agent = project.agents.create_version(
    agent_name=AGENT_NAME,
    definition=PromptAgentDefinition(
        model=os.environ["FOUNDRY_MODEL"],
        instructions=INSTRUCTIONS,
    ),
)
print(f"Agent created (name: {agent.name}, version: {agent.version})")

Run the script twice and the version number goes up. That is the point: a change to the instructions is a new version you can compare and roll back to.

Step 5: hold a conversation

Bind a client to the agent, then create a conversation. Each responses.create call with the same conversation ID adds to one history.

agent_client = project.get_openai_client(agent_name=AGENT_NAME)
conversation = agent_client.conversations.create()

first = agent_client.responses.create(
    conversation=conversation.id,
    input="I bought headphones on order HG-240318-0042. Can I return them?",
)
print(f"Agent: {first.output_text}")

follow_up = agent_client.responses.create(
    conversation=conversation.id,
    input="And how long is the warranty on them if I keep them?",
)
print(f"Agent: {follow_up.output_text}")

The second question says "them" and never repeats the product. It only works if the conversation carries the first turn.

Step 6: put it together

Save steps 3 to 5 in one file, hg_support.py, with the imports at the top. Run it:

python hg_support.py

Check it worked

CheckWhat you should see
Step 3Model says: ready, or something very close.
Step 4, first runAgent created (name: hg-support, version: 1)
Step 4, second runThe same line with version: 2
First answerMentions the 30 day window and the receipt or order ID.
Follow-up answerSays 12 months and treats "them" as the headphones.
PortalBuild > Agents lists hg-support with each version you created.

The exact wording changes from run to run. The facts should not. If the warranty answer says anything other than 12 months, the instructions did not reach the agent you are talking to.

Where this breaks

  • Old code, new package. Samples that call project_client.agents.threads or build a client from a connection string are Foundry (classic). Learn marks the 2.x samples as incompatible with 1.x.
  • 401 or 403. Usually a missing Foundry User assignment on the project, or az login in the wrong tenant. Check with az account show and az account get-access-token --resource https://ai.azure.com.
  • Deployment not found. The model value must match the deployment name exactly. Check it in the portal under the project's models.
  • Every run adds a version. Good for history, noisy in a loop. Create versions from a release step, not on every application start.
  • Instructions are not policy enforcement. The agent states the 30 day rule because the prompt says so. If the returns policy changes, the prompt must change too. The next article moves policy into files the agent searches instead.
  • Python 3.9 or older. The 2.x samples need Python 3.10 or later.

On the brewhouse floor

A distillery's cask team asks the same questions every week: how long has cask 1142 been filled, what strength went in, when is it due for sampling. Distillery B can keep a cask-desk agent in code exactly like hg-support, with the sampling rules in its instructions and a new version each time the rules change. The follow-up test matters here too. "And what about the one next to it?" only gets a sensible answer if the conversation remembers which cask came first.
