A chat app on your own data: a web page in front of a grounded agent

Upload Harbour Goods policy documents to a vector store, attach file search to a prompt agent and put a small Flask page in front of it. Answers come from the files, with the cited filename shown under each reply. The conversation ID never leaves the server.

12 Oct 2026 Foundry as of October 2026 Checked against Microsoft Learn Level 1 Ankur Napa KnowledgeSDKAgents

Short answer

Three pieces. A vector store holds your documents. A prompt agent with the file search tool searches that store before it answers. A small web app sends each message to the agent through the Responses API and keeps one Foundry conversation per browser session. The Foundry SDK does the first two in about twenty lines of Python. The web app is ordinary Flask. Keep the conversation ID on the server, read the file_citation annotations to show sources and run the app under an identity with the Foundry User role. File search carries charges beyond model tokens, so check the pricing page before you load a large library.

What you will build

Harbour Goods support staff keep pasting the same policy paragraphs into chat. The policies live in one short document: returns, delivery promise, electronics warranty and support hours. By the end you will have:

  • A vector store called hg-policies with the sample policy file.
  • A prompt agent hg-policy that answers only from that file.
  • A one-page web app at http://127.0.0.1:5000 that chats with the agent and lists the cited file under each answer.

Download the sample: chat-app-on-your-data.md. It is four short synthetic policies, 283 words in all.

Before you start

  • Everything from Call Foundry from Python: a project, a chat model deployment and the SDK installed.
  • Foundry User on the project, to create and run agents.
  • Storage Blob Data Contributor on the project's storage account, which Learn lists as required for uploading files.
  • A basic or standard agent setup. With the standard setup, your files stay in your own storage and your Azure AI Search resource ingests them.
  • Flask: pip install flask.

Step 1: upload the policies and create the agent

Run this once, from the folder that holds the sample file. It creates the vector store, uploads and indexes the file, then creates the agent.

import os
from pathlib import Path

from azure.ai.projects import AIProjectClient
from azure.ai.projects.models import FileSearchTool, PromptAgentDefinition
from azure.identity import DefaultAzureCredential

project = AIProjectClient(
    endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)
openai = project.get_openai_client()

vector_store = openai.vector_stores.create(name="hg-policies")
with Path("chat-app-on-your-data.md").open("rb") as handle:
    openai.vector_stores.files.upload_and_poll(
        vector_store_id=vector_store.id,
        file=handle,
    )

agent = project.agents.create_version(
    agent_name="hg-policy",
    definition=PromptAgentDefinition(
        model=os.environ["FOUNDRY_MODEL"],
        instructions=(
            "You answer Harbour Goods customer policy questions. "
            "Use file search for every answer and cite the policy file. "
            "If the files do not answer the question, say you do not know "
            "and offer to pass it to support. Keep answers under 60 words."
        ),
        tools=[FileSearchTool(vector_store_ids=[vector_store.id])],
    ),
    description="Policy answers grounded in the Harbour Goods policy file.",
)
print(f"Vector store: {vector_store.id}")
print(f"Agent: {agent.name}, version {agent.version}")

upload_and_poll returns only after ingestion finishes. That matters: an agent asked a question while the file is still indexing answers from the model's general knowledge instead.

The instruction to cite is not decoration. Learn's troubleshooting for missing citations starts with "agent instructions don't request citations".

Step 2: write the web app

Save this as app.py. It holds one Foundry conversation per browser, keyed by a random cookie. The browser never sees the conversation ID.

import os
import uuid

from azure.ai.projects import AIProjectClient
from azure.identity import DefaultAzureCredential
from flask import Flask, jsonify, request

AGENT_NAME = "hg-policy"
project = AIProjectClient(
    endpoint=os.environ["FOUNDRY_PROJECT_ENDPOINT"],
    credential=DefaultAzureCredential(),
)
agent_client = project.get_openai_client(agent_name=AGENT_NAME)
# In memory: run one worker, or use a shared store to scale out
conversations = {}

app = Flask(__name__)


def cited_files(response):
    names = set()
    for item in response.output:
        if item.type != "message":
            continue
        for part in item.content:
            for note in getattr(part, "annotations", None) or []:
                if note.type == "file_citation":
                    names.add(note.filename)
    return sorted(names)


@app.post("/chat")
def chat():
    message = (request.get_json(silent=True) or {}).get("message", "").strip()
    if not message or len(message) > 1000:
        return jsonify(error="Send a message between 1 and 1000 characters."), 400
    session_id = request.cookies.get("hg_session") or str(uuid.uuid4())
    if session_id not in conversations:
        conversations[session_id] = agent_client.conversations.create().id
    try:
        response = agent_client.responses.create(
            conversation=conversations[session_id], input=message
        )
    except Exception:
        app.logger.exception("Agent call failed")
        return jsonify(error="The support agent is unavailable. Try again shortly."), 502
    reply = jsonify(answer=response.output_text, sources=cited_files(response))
    reply.set_cookie("hg_session", session_id, httponly=True, samesite="Strict")
    return reply


@app.get("/")
def page():
    return app.send_static_file("index.html")

Then save the page as static/index.html. It writes replies with textContent, so a model reply can never inject markup into the page.

<!doctype html>
<html lang="en">
<meta charset="utf-8">
<title>Harbour Goods policy help</title>
<main>
  <h1>Ask about returns, delivery or warranty</h1>
  <ol id="log"></ol>
  <form id="ask">
    <label for="q">Your question</label>
    <input id="q" maxlength="1000" required>
    <button>Send</button>
  </form>
</main>
<script>
const log = document.getElementById("log");
function add(text) {
  const li = document.createElement("li");
  li.textContent = text;
  log.append(li);
}
document.getElementById("ask").addEventListener("submit", async (e) => {
  e.preventDefault();
  const q = document.getElementById("q");
  add("You: " + q.value);
  const r = await fetch("/chat", {
    method: "POST",
    headers: {"Content-Type": "application/json"},
    body: JSON.stringify({message: q.value})
  });
  const data = await r.json();
  add(data.error ? "Error: " + data.error : "Agent: " + data.answer);
  if (data.sources && data.sources.length) add("Sources: " + data.sources.join(", "));
  q.value = "";
});
</script>
</html>

Step 3: run it

export FOUNDRY_PROJECT_ENDPOINT="https://<resource-name>.services.ai.azure.com/api/projects/<project-name>"
flask --app app run

Open http://127.0.0.1:5000 and ask the questions below.

Check it worked

Every expected answer comes straight from the sample file.

QuestionExpected answer
How many days do I have to return headphones?30 days, with the receipt or order ID.
How long is standard delivery to Pune?5 working days (Pune is not in the metro list).
What is the delivery charge on an INR 500 order?INR 79, because free delivery starts at INR 999.
Does the warranty cover a phone dropped in water?No, liquid damage is excluded.
Is ST-099 one of your stores?No.
What is your price match policy?It does not know. It offers to pass the question on.

Under each answer you should see Sources: chat-app-on-your-data.md. The last question is the important one. A grounded agent that invents a price match policy is worse than no agent. Then ask "and what if I lost the receipt?" straight after the first question. The answer should mention the order ID, which shows the conversation is carrying context.

Where this breaks

  • Ingestion not finished. Answers that sound right but carry no citation usually mean the agent ran before indexing completed, or the instructions do not ask for citations.
  • Missing storage role. Upload fails without Storage Blob Data Contributor on the project's storage account.
  • One worker only. The conversation map lives in process memory. Learn's App Service tutorial makes the same choice and runs one Gunicorn worker for it. Scale out and you need a shared store.
  • File search costs. Learn flags additional charges for file search beyond token fees. A few policy files cost little; a scanned archive is a different conversation. Check the Azure pricing page for your region.
  • Annotations shape. The cited_files helper reads the Responses output items. If your SDK version shapes annotations differently, print response.output once and adjust the loop.
  • Deploying it. Locally the app uses your az login. On App Service or Container Apps, give the app a managed identity and assign it Foundry User on the project. No keys in app settings.

On the brewhouse floor

Winery C has a cellar handbook nobody reads at harvest: sulphur additions, topping schedules, which tanks can take a pump-over. Upload the handbook to a vector store, attach file search to a cellar-help agent and put a page on the cellar tablet. The cellar hand asks "can tank T-12 take a pump-over today?" and gets the rule with the handbook cited under it. When the answer is not in the handbook, the agent should say so. In a cellar, a confident guess about additions is the expensive kind of wrong.
