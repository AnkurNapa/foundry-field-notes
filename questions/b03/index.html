Models and deployments

B03 Question

Provisioned throughput or pay as you go?

Checked 12 Oct 2026 Ankur Napa

The answer

Standard deployments share capacity across customers and bill per token. Provisioned deployments reserve model processing capacity for you, measured in provisioned throughput units (PTU). They bill per PTU per hour or through an Azure reservation.

Learn says provisioned fits when you have predictable traffic, latency-sensitive users, production-scale volume where per-token billing gets expensive or an interactive agent where variable response times hurt. Standard stays better for development, testing, low volume and traffic too variable to size.

Points that catch teams:

  • PTU quota is per subscription, per region and per deployment type.
  • Each model has a minimum PTU count. The tokens per minute you get per PTU also vary by model.
  • Spillover can send overflow requests from a provisioned deployment to a standard one in the same resource. Overflow requests bill at standard token rates.
  • Provisioned deployments are not auto-upgraded when a model version retires. You migrate them yourself.

Size it with the capacity calculator in the portal, using real request shapes from your logs. For the Harbour Goods agent, run on Global Standard through the pilot, measure tokens per minute at the evening peak, then decide.

Decision rule

Stay on standard pay as you go while traffic is uncertain. Move to provisioned throughput once production traffic is predictable and latency must stay consistent.

Watch out

A provisioned deployment bills every hour whether or not it is used. Scaling down releases capacity back to the region, with no guarantee you get it back.
