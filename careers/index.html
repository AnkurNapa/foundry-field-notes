AI engineer

Turns a business question into a working AI app. Picks and deploys the model, writes the prompts and structured outputs, grounds answers in company data and keeps cost and latency in check.

Learning path, in order

  1. 0 Foundry in one picture Foundations
  2. 0 Models, deployments and tokens Foundations
  3. 0 Grounding and RAG, plainly Foundations
  4. 1 Deploy your first model and call it Beginner
  5. 1 Choose a model from the catalogue Beginner
  6. 1 Ground an agent in your files Beginner
  7. 1 Your first Azure AI Search index Beginner
  8. 1 Run your first evaluation Beginner
  9. 1 Keyless auth with Entra ID Beginner
  10. 1 Call Foundry from Python Beginner
  11. 1 A chat app on your own data Beginner
  12. 2 Deployment types and quota Practitioner
  13. 2 Model router Practitioner
  14. 2 Prompts and structured outputs Practitioner
  15. 3 Latency, throughput and caching Professional

Certifications

  • AI-901 Azure AI FundamentalsAI concepts and building with Microsoft Foundry. Replaced AI-900, which retired on 30 June 2026.
  • AI-103 Azure AI Apps and Agents Developer AssociateDeveloping AI apps and agents on Azure with Foundry and Python. Replaced AI-102, which retired on 30 June 2026.

Portfolio project

A Harbour Goods support assistant that answers returns, delivery and warranty questions from the three policy documents with a citation on every answer, returns order lookups as JSON against a schema, signs in with Entra ID and reports the token cost of a typical conversation.

Price it with the token cost calculator

Interview questions to master

  • Which deployment type: Global Standard, Data Zone, Standard, Provisioned or Batch?
  • When should I use model router instead of picking one model?
  • Provisioned throughput or pay as you go?
  • File search tool or my own Azure AI Search index?
  • How do I make retrieval answers cite their sources reliably?
  • API keys or Microsoft Entra ID?
  • How do I estimate token cost before launch?
  • How do I move from an Azure OpenAI resource to Foundry?

Agent developer

Builds agents that do work, not just chat. Chooses between prompt and hosted agents, wires tools and MCP servers, designs multi-agent hand-offs and puts a person in the loop where money or risk is involved.

Learning path, in order

  1. 0 What an agent is and is not Foundations
  2. 0 Prompt, hosted or Responses API Foundations
  3. 1 Your first prompt agent Beginner
  4. 1 Give an agent built-in tools Beginner
  5. 1 Ground an agent in your files Beginner
  6. 2 Toolboxes and MCP servers Practitioner
  7. 2 Hosted agents with Agent Framework Practitioner
  8. 2 Multi-agent workflows Practitioner
  9. 2 Foundry IQ knowledge bases Practitioner
  10. 2 Agent identity Practitioner
  11. 2 Voice agents with Voice Live Practitioner
  12. 3 Long-running agents and human approval Professional
  13. 3 Publish to Teams and Microsoft 365 Copilot Professional

Certifications

  • AI-103 Azure AI Apps and Agents Developer AssociateDeveloping AI apps and agents on Azure with Foundry and Python. Replaced AI-102, which retired on 30 June 2026.
  • AI-200 Azure AI Cloud Developer AssociateBack-end development on Azure for AI workloads. Replaced AZ-204.

Portfolio project

A Harbour Goods support agent that looks up order HG-240318-0042 through an MCP tool, cites the returns policy, pauses for a person to approve any refund above INR 5,000 and is published to Microsoft Teams with its own agent identity.

Interview questions to master

  • Prompt agent, hosted agent or plain Responses API?
  • When should an agent call an MCP server instead of a function tool?
  • One agent or a multi-agent workflow?
  • Foundry IQ knowledge base or plain Azure AI Search?
  • How do I catch prompt injection hidden in documents my agent reads?
  • Which role does a developer need on a Foundry project?

AI platform engineer

Keeps Foundry safe, affordable and repeatable for every team that uses it. Owns infrastructure as code, roles, private networking, quota, cost alerts and the migrations off older resources.

Learning path, in order

  1. 0 The developer toolchain Foundations
  2. 0 Who can do what: Foundry roles Foundations
  3. 1 Keyless auth with Entra ID Beginner
  4. 2 Deployment types and quota Practitioner
  5. 2 Agent identity Practitioner
  6. 2 Infrastructure as code with Bicep and azd Practitioner
  7. 2 CI/CD for agents Practitioner
  8. 3 Private networking for Foundry Professional
  9. 3 Cost control Professional
  10. 3 Foundry Local and the edge Professional
  11. 3 Migrate from Azure OpenAI and hub projects Professional
  12. 4 Control plane and Azure Policy at scale Architect
  13. 4 An AI landing zone Architect

Certifications

  • AZ-104 Azure Administrator AssociateIdentity, networking, storage and monitoring on Azure. The base for platform work.
  • AI-103 Azure AI Apps and Agents Developer AssociateDeveloping AI apps and agents on Azure with Foundry and Python. Replaced AI-102, which retired on 30 June 2026.
  • SC-500 Cloud and AI Security Engineer AssociateSecuring cloud and AI workloads, including Foundry guardrails and agent identity. Successor to AZ-500.

Portfolio project

A Bicep and azd template that stands up a Foundry resource with dev and prod projects, private endpoints, keyless access, a token quota per app and a monthly cost alert, plus a runbook for moving a standalone Azure OpenAI resource across without changing client code.

  • Foundry resource with projects, or a hub-based project: which do I create today?
  • How many Foundry projects should a team have?
  • API keys or Microsoft Entra ID?
  • Do I need private networking for Foundry? What breaks when I add it?
  • Which role does a developer need on a Foundry project?
  • How do I stop one app using up the whole quota?
  • How do I move from an Azure OpenAI resource to Foundry?
  • How do I move from hub-based projects to Foundry projects?

AI quality and evaluation engineer

Defines what good means for each AI app and measures it. Builds test sets, chooses and writes evaluators, runs red teaming, watches quality in production and turns all of it into a release gate.

Learning path, in order

  1. 0 Why evaluation comes before launch Foundations
  2. 0 Responsible AI in practice Foundations
  3. 1 Run your first evaluation Beginner
  4. 1 Trace an agent run Beginner
  5. 1 Content filters and blocklists Beginner
  6. 2 Built-in evaluators Practitioner
  7. 2 Custom evaluators and test sets Practitioner
  8. 2 Prompt shields and groundedness Practitioner
  9. 2 CI/CD for agents Practitioner
  10. 3 Retrieval quality Professional
  11. 3 AI red teaming Professional
  12. 3 Monitor in production Professional
  13. 3 Agent optimizer Professional
  14. 4 Evaluation strategy that gates releases Architect

Certifications

  • AI-103 Azure AI Apps and Agents Developer AssociateDeveloping AI apps and agents on Azure with Foundry and Python. Replaced AI-102, which retired on 30 June 2026.
  • AI-300 Machine Learning Operations Engineer AssociateDeployment, evaluation, observability and fine-tuning in production. Replaced DP-100.

Portfolio project

A 60-question Harbour Goods test set with expected answers and sources, built-in and custom evaluators, one red teaming run with fixes plus a pipeline gate that blocks a release when groundedness or task completion falls below the agreed score.

Interview questions to master

  • Which evaluators should run before every release?
  • What do the default content filters block? Should I change them?
  • How do I catch prompt injection hidden in documents my agent reads?
  • Do I need AI red teaming before go-live?
  • Fine-tune, or fix the prompt and retrieval first?
  • How do I make retrieval answers cite their sources reliably?
